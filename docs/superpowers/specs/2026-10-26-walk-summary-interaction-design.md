# 산책 요약과 주간 기록 전환 설계

2026-10-26. 상태는 **시안 반영 완료, 앱 구현 설계 검토 전**이다.
이 문서는 완료 화면의 PRD와 TRD를 함께 정리한다. GPS 분류 정책, 보안 수정,
배터리 정책을 승인하거나 기존 기록을 일괄 재계산하는 문서가 아니다.

## 사용자가 정한 방향

- 차량 이동 앞뒤 걷기는 같은 산책에 남긴다.
- A안처럼 이번 산책의 문구와 걸은 거리를 먼저 보여 준다.
- B안의 누적 성취감이 드러나는 말투를 함께 쓴다.
- 지도 또는 그 주변 영역을 가로로 넘기면 주간 누적량을 볼 수 있게 한다.
- 조작을 간결하게 다듬고 업계 지침을 참고한다.

기존 조사와 두 시안은 [산책 효용 검토](../verification/2026-10-25-walk-value-audit.md)에
있다. 아래의 세부 동작, 시간 범위와 구현 방식은 사용자의 위 요구를 구체화한
설계 판단이다. 각각을 사용자가 이미 승인했다고 해석하지 않는다.

## 목적과 성공 조건

산책을 마친 사람이 첫 화면에서 자신이 걸은 양을 이해하고, 한 번의 조작으로
이번 산책이 누적 기록에 더한 양을 확인한다. 경로와 누적량을 오갈 때 이번 산책의
수치가 다른 수치로 교체되어 혼동하지 않게 한다.

성공 조건은 다음과 같다.

1. 첫 화면의 읽기 순서가 완료 안내, 거리와 시간, 평균 속도, 경로 순서다.
2. 누적량을 보려고 지도 영역을 밀어도 지도가 뜻하지 않게 움직이지 않는다.
3. 밀기 동작을 모르거나 사용할 수 없어도 이름이 있는 버튼으로 같은 화면에 접근한다.
4. 누적 화면에서도 미확인 구간과 수정 진입점을 찾을 수 있다.
5. 정확하지 않은 측정을 따뜻한 문구로 확정 사실처럼 보이게 하지 않는다.

## 정보 구조와 문구

완료 화면 위쪽에는 다음 내용을 둔다. 여기서 고정은 가로 전환 중 같은 내용을
유지한다는 뜻이며, 세로 스크롤에서 화면에 달라붙는 헤더를 뜻하지 않는다.

- 날짜와 기록 시작/종료 시각.
- 주 문구 `이동은 나누고, 걸은 만큼 남겼어요.`
- 보조 문구 예시 `오늘의 28분도 차곡차곡. 이번 주 네 번째 산책을 더했어요.`
- `걸은 거리 2.00km`, `걷기 시간 28분`.
- `걷기 평균 속도 4.3km/h`와 `계산 보기`.

위 문구는 걷기와 차량 구간을 구분한 새 기록의 예시다. 차량 구간이 없는 기록에는
`오늘도 걸은 만큼 남겼어요.`처럼 분리하지 않은 이동을 분리했다고 말하지 않는다.
걷기로 판정할 수 없는 기록에는 걷기 성과를 확정하는 문구를 쓰지 않는다.
횟수와 누적량을 불러오지 못하면 보조 문구를 생략한다. 임의 숫자나 0으로 대체하지 않는다.
길거나 작은 수치는 줄바꿈과 단위로 표현하고, 목표 실패나 타인과의 비교를 추가하지 않는다.

아래 영역에는 `이번 경로`와 `이번 주`라는 두 탭을 둔다. 첫 진입은 경로다.

| 부분 | 이번 경로 | 이번 주 |
|---|---|---|
| 주요 내용 | 걷기와 제외 구간을 구분한 지도 미리보기 | 주간 합계와 이번 산책이 더한 양 |
| 보조 내용 | 걷기와 차량 구간 범례, 앞뒤 걷기를 이어 담았다는 안내 | 요일별 기록, 기록한 횟수, 조건을 만족하는 이전 주 비교 |
| 상세 진입 | 지도 크게 보기 | 주간 기록 보기 |
| 계속 보이는 내용 | 위쪽의 이번 산책 수치와 아래의 확인 필요 안내 | 왼쪽과 동일 |

색만으로 경로를 구분하지 않고 선 모양과 텍스트를 함께 쓴다. 제외된 구간의 실제
관측 경로만 표시하며, 빈 GPS 구간을 가로질러 이동한 경로를 만들어 그리지 않는다.
시안의 점선은 가상 시나리오를 설명하기 위해 그린 경로다.

`확인할 구간이 2분 있어요`와 `전체 구간 살펴보기`는 전환 영역 밖에 둔다.
확인할 구간이 없으면 경고 영역을 만들지 않는다. 해당 시간의 집계 포함 여부는
실제 측정 정책을 따른다. 이번 UI 변경만으로 불확실 시간을 새로 제외하지 않는다.

## 전환과 지도 조작

- 탭을 누르거나 해당 영역을 좌우로 밀면 같은 페이지 상태를 바꾼다.
- 두 페이지만 둔다. 자동 넘김, 무한 반복, 자동으로 숫자가 올라가는 효과를 넣지 않는다.
- 선택 탭은 바탕, 밑줄, 접근성 선택 상태로 구분한다. 작은 점 두 개와 `1 / 2`는
  보조 표시이며 유일한 탐색 수단으로 쓰지 않는다.
- 요약의 지도 미리보기는 수동 이동과 확대를 받지 않는다. 가로는 페이지 전환,
  세로는 전체 화면 스크롤이 처리한다. 여러 손가락이나 제스처 취소는 페이지를
  임의 확정하지 않으며 OS 가장자리 뒤로가기를 가로채지 않는다.
- 지도 탐색은 `지도 크게 보기`에서 별도 화면으로 연다. 그 화면에서는 지도 이동과
  확대, 전체 경로 맞춤을 제공하고 누적 페이지로 넘기지 않는다. 확대/축소와 이동을
  버튼으로도 제공한다. 뒤로가기는 상세 지도만 닫는다.
- 큰 지도를 닫으면 이전 요약 페이지와 스크롤 위치, 탐색 초점을 복원한다.
- 새 산책을 열면 경로부터 시작한다. 같은 기록에서 상세 보기 후 돌아올 때는 선택을
  유지한다. 저장소 전역에 모든 기록이 공유하는 페이지 번호를 저장하지 않는다.
- 전환은 약 220ms의 짧은 수평 이동으로 표현한다. 시간은 시안의 설계값이며 표준의
  의무값이 아니다. OS 동작 줄이기 설정에서는 비필수 애니메이션을 제거한다.
- 두 패널 높이를 같은 내용 공간에 맞추어 전환할 때 아래 버튼이 튀지 않게 한다.
  큰 글자에서는 공간 자체가 늘어나도록 하고 일정 높이로 텍스트를 자르지 않는다.

미리보기 지도와 넘기기를 함께 넣는 대안, 탭만 두는 대안, 요약 전체를 넘기는 대안도
검토했다. 첫 번째는 동작 의도가 충돌하고, 두 번째는 사용자가 원한 밀기 동작을
없애며, 세 번째는 이번 산책 수치까지 화면에서 사라진다. 위 방식을 선택한 이유다.

## 수치와 주간 범위의 계약

이번 변경이 측정 정책을 대신하지 않게 한다.

- 현재 앱은 `totalDistanceM`와 `movingTimeS`로 완료 평균을 계산한다. 기존 기록의
  이동 시간이 모두 확정 걷기 시간이라는 근거는 없다. 기존 데이터만 사용하는
  구현 단계에서는 `포함 거리`, `이동 시간`, `이동 평균 속도`처럼 실제 값의 의미를
  유지한다. 새 분류 정책이 승인되고 적용된 기록에만 확정 걷기 표현을 사용한다.
- 계산 설명에는 같은 포함 구간의 거리와 시간, 제외 기준을 보여 준다. 실제 계산은
  반올림 전 거리와 초 단위 시간으로 하고, 표시값 차이도 설명한다. 분모가 없거나
  0이면 속도를 만들지 않고 `측정되지 않음`으로 표시한다.
- 누적량은 산보에 기록한 값이다. 건강 앱의 일일 걸음 수나 기록하지 않은 시간을
  합쳐 이번 산책의 성과처럼 보여 주지 않는다. 기록 없음은 걷지 않았다는 뜻이 아니다.
- 새 기록의 주간 범위는 표시 시간대의 월요일 00:00부터 기록 종료 시점까지다.
  과거 기록을 열면 `그 주`와 날짜 범위를 사용한다. 현재 주를 붙여 과거 요약의
  성과가 계속 변하는 것처럼 만들지 않는다.
- 비교는 전주 월요일부터 같은 요일과 현지 시각까지다. 일광절약시간이 있는 경우
  고정된 7×24시간을 빼지 않고 기존 달력 유틸리티를 사용한다. 시간대는 화면에
  사용한 시간대로 통일한다. 미래 기록이나 종료 이후 기록은 더하지 않는다.
- 주간 경계를 가로지른 기록은 시간 구간과 집계 근거가 있을 때 해당 주의 겹치는
  부분을 계산한다. 레거시 세션 합계만 있어 안전하게 나눌 수 없으면 균등 배분하지
  않고 누적을 불완전 상태로 표시하며 전주 비교와 순번 문구를 숨긴다.
- 걷기 기준이 서로 다른 기록, 미확인 집계, 누락된 과거 시간이 섞이면 ‘확정 걷기’
  합계나 개선량을 만들지 않는다. 사용 가능한 동일 기준의 포함/이동 통계로 표시하거나
  `일부 기록은 합산하지 못했어요`와 해당 기록 접근을 제공한다.
- 이번 산책의 주간 기여분은 합계에 이미 포함한다. 이 값을 다시 더하지 않는다.
  주간 산책 횟수는 해당 범위에 유효한 포함 활동이 있는 서로 다른 세션 수다.
  차량 전후 두 걷기를 두 번으로 세지 않는다. 가져온 중복 ID는 기존 저장소 규칙을 따른다.
- 전주 비교가 성립하지 않으면 비교 문구만 생략한다. 현재 기록과 지도는 계속 볼 수 있다.

완료 후 구간을 수정했을 때는 이번 산책 수치와 그 주 집계를 함께 무효화해 같은
기준으로 갱신한다. 계산 중에는 확정 문구를 잠깐 이전 값과 섞지 않는다. 기록의 원본과
사용자 라벨을 자동 수정하거나 삭제하지 않는다.

## Flutter에 적용하는 범위

기존 Flutter, Riverpod, `flutter_map`과 디자인 토큰을 사용한다. 캐러셀 패키지,
분석 SDK, 새 외부 서비스는 추가하지 않는다.

- `lib/features/session_detail/session_detail_screen.dart`의 완료 요약 순서를 조정하고,
  위쪽 수치와 아래 두 패널을 분리한다. 기존 메모, 제외 취소, 재생, 내보내기 진입을
  새 요약 때문에 없애지 않는다. 구간 선택이 경로를 강조해야 할 때는 경로 페이지를
  명시적으로 보여 준다. 지도에서 재생한 위치는 누적 화면 전환만으로 초기화하지 않는다.
- 전환은 Flutter 기본 `PageView`와 `PageController`로 구성한다. 웹 시안의 직접 작성한
  포인터 임계값을 앱에 복사하지 않는다. 패널은 정확히 두 개이며 선택 상태는 하나다.
- 세로 목록 안의 `PageView`는 높이 제약이 필요하다. 텍스트 크기와 폭에 따라 양쪽
  내용에 충분한 높이를 계산하고 검증한다. 무제한 높이나 고정 300px를 그대로 넣지 않는다.
  접근성 대형 글자에서는 세로 스크롤로 끝까지 접근할 수 있어야 한다.
- `lib/shared/widgets/route_map.dart`는 현재 세로 스크롤 충돌을 막기 위해 pinch zoom만
  허용한다. 새 요약 미리보기와 큰 지도에 필요한 상호작용 설정을 구분하되, 다른 화면의
  지도를 모두 바꾸는 전역 동작 변경은 하지 않는다.
- 요약과 큰 지도가 독립 타일 클라이언트를 계속 동시에 돌리지 않게 한다. 큰 지도를
  닫은 뒤 자원을 해제하고 지도 오류/재시도/원본 경로 표시를 유지한다. 누적 화면을
  볼 때 보이지 않는 지도 재생은 멈추고 위치는 보존한다. 새 위치 구독은 만들지 않는다.
- 주간 데이터는 요약 진입 시 제한된 날짜 범위로 한 번 읽고 갱신 근거가 있을 때만
  다시 읽는다. 밀 때마다 DB 재집계나 위치 요청을 하지 않는다. 기존 건강 데이터
  provider를 호출해 불필요한 건강 권한 조회를 유발하지 않는다.
- 현재 `WalkRepository.dailyStats()`는 `duration_s`를 합한다. 이를 그대로 가져와
  이동/걷기 누적 시간이라고 부르지 않는다. 호환 단계에서는 `moving_time_s`의
  존재와 집계 범위를 확인하고, 확정 걷기 단계에서는 같은 정책으로 판정한 구간을
  합한다. 기존 일일 통계 전체의 의미를 이 화면 때문에 전역 변경하지 않는다.
- 경로/주간/이번 산책 요약의 실패를 분리한다. 지도 불러오기 실패는 주간 통계를,
  주간 통계 오류는 이번 산책과 구간 수정/반출을 막지 않는다.

이 문서는 UI 적용 설계다. 주간 집계의 구간별 근거가 부족하면 구현 계획에서 제한된
호환 표시를 먼저 명시해야 한다. UI를 빨리 붙이기 위해 아직 없는 정확성을 전제로
필드나 숫자를 만들지 않는다. GPS 판정과 배터리 정책은 별도 설계를 계속한다.

## 접근성과 검증

- 주요 터치 영역을 48×48 논리 픽셀 이상으로 둔다. 색상 외에 이름과 선택 상태가 있다.
- 키보드로 탭에 진입하고 좌우 화살표, Home/End로 선택한다. 비활성 패널은 접근성
  탐색과 Tab 순서에서 제외하고 선택 페이지를 안내한다. 버튼에 갇히는 초점은 만들지 않는다.
- TalkBack/VoiceOver 사용자가 밀기 없이 탭 이름으로 같은 기능에 접근하도록 한다.
  일반 터치 넘김을 화면 읽기 도구의 탐색 제스처보다 우선하지 않는다.
- 텍스트 배율 100%, 160%, 200%와 좁은 화면, 가로 화면, 긴 단위, 다크 모드에서
  텍스트 누락과 수평 넘침을 검사한다. 웹 시안 확인은 Flutter 실기기 검증의 대체가 아니다.
- 완료 화면 첫 진입, 양방향 넘김, 작은 손떨림과 취소, 세로 스크롤, 탭 직접 선택,
  지도 확대 후 복귀, 구간 편집 후 통계 동기화, 지도/통계 각각의 실패를 검증한다.
- 합계의 중복 반영, 주 경계, 시간대 변경, 기록 없음, 동일 기준을 충족하지 않는
  레거시 기록을 집계 테스트에 넣는다. 원본 값이 UI 전환 때문에 변경되면 실패다.

이번 브라우저 시안은 가상 데이터로 전환을 평가하는 일회성 구현이다. 제품 코드와
별도로 로컬 `.superpowers/`에 보관한다. 실제 CARTO, GPS, 건강 데이터 요청을 하지 않는다.

2026-10-26 브라우저 확인 결과는 다음과 같다.

- 버튼, 좌우 실제 드래그, 키보드 ArrowRight/Home으로 페이지를 바꿀 수 있었다.
  상단 2.00km와 28분을 유지했고 접근성 트리에는 선택한 패널 하나만 나왔다.
- 큰 지도에서 확대 버튼으로 100%에서 125%로 바뀌고 닫은 뒤 경로 화면으로 돌아왔다.
- 340px 폭의 큰 글자에서 본문 넘침이 없었다. 실제 viewport 320px에서는 바깥 CSS
  grid의 최소 폭 때문에 전체 폭이 389px로 늘어나는 문제를 발견해 수정했다.
  수정 후 큰 글자를 켜도 문서 폭은 320px였고 조사한 본문 요소에 가로 넘침이 없었다.
- 동작 줄이기를 켰을 때 패널 전환 시간이 `0s`였다. 확인 시 브라우저 경고/오류
  로그는 비어 있었다. 테스트용 viewport와 표시 옵션은 원래 상태로 돌렸다.
- 실제 모바일 터치, OS 화면 읽기 도구, 200% 시스템 글자, Flutter 렌더링, GPS,
  배터리 절감은 이번 시안에서 검증하지 않았다.

## 참고한 공식 지침과 설계 판단의 구분

- [W3C 탭 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)의 역할, 선택 상태와
  키보드 탐색을 웹 시안에 적용했다.
- [W3C 드래그 동작](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html)은
  끌기 대신 단일 클릭/탭으로 수행할 수 있는 경로를 안내한다. 이름 있는 탭이 그 대안이다.
- [W3C 캐러셀 안내](https://www.w3.org/WAI/tutorials/carousels/)의 발견 가능성과 사용자
  제어 문제를 고려해 자동 넘김 없이 두 내용과 그 이름을 계속 드러낸다.
- [Flutter 접근성](https://docs.flutter.dev/ui/accessibility)은 터치 크기, 대비, 실제
  화면 읽기 도구 검증과 큰 글자 사용성을 안내한다.
- [Flutter PageView](https://api.flutter.dev/flutter/widgets/PageView-class.html)는 같은
  viewport 크기의 페이지, controller와 페이지 보존 동작을 설명한다.

지도 탐색 분리, 220ms 전환, 날짜 범위, 보조 문구와 패널 높이 설계는 위 문서가
요구한 정답이 아니라 산보의 문제에 맞춘 제안이다. 실제 사용성 우위나 배터리 개선을
측정했다고 주장하지 않는다. 사용자 지침에 따라 재위임 없이 직접 설계 검토했다.
