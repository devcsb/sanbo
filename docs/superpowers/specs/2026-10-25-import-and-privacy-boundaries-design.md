# 백업 입력과 데이터 반출 경계 개선 설계

작성일은 2026-10-25다. 상태는 **사용자 검토 전**이며 아직 구현 승인을 받지 않았다.
근거는 [후속 비판적 검토](../../security/2026-10-25-critical-review.md)다.

2026-10-28 [요약 구현 이후 검토](../../security/2026-10-28-critical-review.md)에서
현재 `6f2e0ae` 기준으로 백업 집계 실패와 계산량 확대, 원본 클립보드 반출을 다시
재현했다. 요약 UI 구현은 이 설계의 보안 수정을 포함하지 않으며, 본 문서는 여전히
구현 승인 전이다. 첫 단계로 이 범위를 진행할 것을 권한다.

작성 후 사용자가 차별점, 배터리, 차량 혼입, 산책 효용과 속도 표시의 다섯 문제를
설명했다. [제품 추가 검토](../verification/2026-10-25-walk-value-audit.md)를 반영해
전체 순서를 정해야 하며 이 문서만으로 전체 제품 고도화 범위를 확정하지 않는다.

## 의도와 범위

사용자는 공개한 앱을 비판적으로 검토하고 놓친 오류, 보안 문제, 불필요한 부분을
찾아 개선해 달라고 요청했다. 이 설계는 먼저 확인한 외부 입력 처리와 데이터 반출
문제를 다룬다. 기존 Flutter, SQLite, Android/Kotlin과 iOS/Swift 구성을 유지한다.
새 서버나 새 SDK 없이 현재 파일 저장 기능을 재사용한다.

사용자의 기존 결정은 원본 GPS와 사용자 수정 보존, 같은 세션의 중복 복원 방지,
로컬 기록 우선이다. 아래 크기/계산 상한과 공유 방식은 **작성자의 제안**이며
사용자가 이미 합의한 조건으로 표현하지 않는다.

## 목표와 하지 않을 일

1. 큰 파일과 조작된 metadata를 앱이 제한 없이 읽지 않는다.
2. 작은 악성 백업으로 집계 화면을 망가뜨리거나 무제한 계산을 시작할 수 없게 한다.
3. 원본 위치/메모 반출은 내용을 알리고 시스템 파일 선택기로 처리한다.
4. 이미 손상된 집계가 있어도 사용자가 기존 기록 목록에 접근할 수 있게 한다.
5. 기기 저장과 OS 백업, 암호화 여부를 정확하게 설명한다.

기존 DB를 일괄 삭제/재계산하거나 잘못된 값을 몰래 수정하지 않는다. 서명 키,
CARTO 키/요금제, 고속 제외 기준, GPS 거리 계산 정책을 바꾸지 않는다. 광고,
회원 서버, 백업 암호화, iOS 배포, OS 백업 제외 기능 신설은 이 단계의 범위가 아니다.

## 1. Android에서 읽기 전에 파일을 제한한다

- 백업 가져오기는 기존 native 파일 처리 통로에 제한된 읽기를 추가한다. 전체 파일을
  먼저 읽는 `file_selector_android` 경로는 Android 백업 가져오기에서 사용하지 않는다.
  desktop의 파일 선택과 iOS 기존 경로는 유지한다.
- 시스템 문서 선택기를 사용하고 새 저장소 권한을 요청하지 않는다. 취소는 취소,
  provider 오류는 실패로 구분한다. 크기를 모르는 정상 문서도 읽을 수 있다.
- 제공자가 보고한 크기가 50MiB보다 크면 바로 거부한다. 크기가 없거나 작아도
  읽은 byte를 직접 세어 50MiB + 1에서 중단한다. 제공된 크기로 배열을 만들지 않는다.
- UI 스레드에서 파일을 복사하지 않는다. 한 번의 제한된 읽기로 앱 전용 임시 파일을
  만들고, Dart에 전체 byte와 파일 사본을 중복 전달하지 않는다.
- 한 번에 한 작업만 허용한다. 화면/Activity 종료, 취소, 오류, Dart 읽기 완료 후
  소유한 임시 파일을 정리한다. 지연된 결과가 새 작업을 완료시키지 않도록 기존
  내보내기의 작업 식별 방식과 맞춘다. 중단된 작업의 사본은 다음 시작에 회수한다.
- 30초 읽기 제한을 제안한다. 제한 시 provider 읽기를 취소/닫고 사용자가 재시도할
  수 있도록 한다. Dart Future timeout만 두고 native 읽기를 계속하는 구현은 피한다.
- 외부 파일명은 표시 용도로만 제한해 사용한다. 실제 임시 경로는 앱이 만들며 원본
  URI/선택한 원본 파일을 삭제하지 않는다. 기존 플러그인 cache를 무차별 삭제하지 않는다.
- iOS/desktop의 Dart 읽기도 제한된 stream으로 처리한다. iOS 시스템 picker 자체의
  import copy까지 제한했다고 주장하지 않는다. 이 부분은 iOS 공개 전 검증 항목이다.

50MiB는 파일 크기 상한이며 파싱 후 전체 메모리가 50MiB라는 의미는 아니다.
최대 크기 합성 입력의 메모리/취소 동작을 Android에서 검증한다.

## 2. 백업 숫자와 시간 범위에 일관된 상한을 둔다

- 외부 입력 경계에서 검증하고 전체 import transaction의 원자성을 유지한다.
- 한 세션의 `ended_at - started_at`은 0 이상 7일 이하로 제한한다. 새 기록의 5시간
  정책보다 넓게 잡아 예전 기록을 수용하되, 사실상 무한한 분 생성은 막는다.
- 7일은 **계산 자원 보호를 위한 제안**이다. 초과 백업은 이유를 알리고 가져오기를
  취소한다. 원본 파일은 그대로 둔다. 사용자 동의 없는 부분 복원/절단은 하지 않는다.
- 재계산 진입점에도 같은 제한을 둔다. 이미 DB에 들어간 긴 기록은 읽기/삭제/원본
  반출을 허용하고, 제외 편집/재계산만 명확한 오류로 거부한다. 사용자 DB에 자동
  데이터 변경이나 숨겨진 마이그레이션을 실행하지 않는다.
- `duration_s`, `moving_time_s`, `stationary_time_s`는 실제 범위의 올림 초를 넘지
  못한다. 이동+정지 합은 반올림 차이 1초를 허용한다. 제외로 줄어든 duration을 실제
  벽시계 범위와 강제로 같게 만들지 않는다. null인 과거 필드는 그대로 허용한다.
- 좌표는 기존 범위를 유지한다. 거리/속도/정확도/고도 등 나머지 수치에는 절댓값
  1e9의 넉넉한 저장 안전 상한을 제안한다. 기존 필드의 음수 허용 여부는 유지한다.
  이 값은 측정 정확도 기준이나 정상 보행 판정이 아니다.
- 샘플 수는 기존 테이블 상한 500,000 이내에서 다룬다. 실제 입력보다 큰 수로 메모리를
  사전 할당하지 않는다. 시간/숫자를 정수로 바꾸기 전에 범위를 검사한다.
- 전체 파일 50MiB, 테이블당 행 500,000 제한은 유지한다. 분 객체 생성은 최대
  10,081개로 제한한다. 세션이 분 중간에 시작하면 양끝 부분 분이 생기는 점을 포함한다.
- 제외 참조 검사는 ID map으로 해당 제외 1건의 세션/시간을 확인한다. 분마다 모든
  제외를 다시 스캔하지 않는다. 재계산도 정렬된 제외를 순회해 분×제외 수의 곱을 피한다.

서로 유효한 수치의 조작을 인증하는 기능은 아니다. 사용자가 선택한 평문 백업의
무결성을 검증해 안전하게 처리하는 범위다. 거리/속도를 현재 알고리즘으로 다시 써서
과거 결과를 바꾸는 방식은 사용하지 않는다.

## 3. 기존 이상값 때문에 목록까지 막히지 않게 한다

집계와 기록 목록의 성공을 분리한다. 집계가 실패하면 합계를 0으로 위장하지 않고
‘일부 통계를 표시할 수 없어요’라고 알리면서 목록/상세/삭제/내보내기를 유지한다.
유한하지 않은 합계나 정수 overflow도 같은 경로에서 처리한다. 개별 기록의 비정상
숫자는 안전한 표시로 대체하되 DB 원본을 고치지 않는다. 정상 화면에는 안내를 추가하지 않는다.

이 설계에서 기존 이상값 복구는 사용자에게 접근 수단을 남기는 것을 뜻한다.
자동 수치 보정이나 정상으로 보이는 임의 값 저장을 뜻하지 않는다.

## 4. 원본은 파일로, 요약은 최소한의 정보로 공유한다

- 개별 산책의 NDJSON 형식과 원본/제외 정보를 보존하되 클립보드 전송은 제거한다.
  기존 시스템 파일 저장 기능을 재사용해 `.ndjson` 파일로 내보낸다. desktop 파일
  종류 필터도 확장자에 맞춰 처리하며 `.sanbo` 전체 백업과 혼동하지 않는다.
- 저장 전에 정밀 좌표, 시간, 메모, 제외된 원본까지 포함하고 암호화하지 않았음을
  알린다. 사용자가 취소하면 파일/클립보드에 기록하지 않는다.
- 일반 ‘요약 복사’는 시각, 거리, 시간, 평균 속도와 페이스 등 요약 지표만 포함한다.
  메모, 장소 이름/주소, 원본 좌표는 제외한다. 활동 구간의 상세 목록도 원본 파일에서
  확인하도록 한다. 이것은 기존 복사 결과를 줄이는 제안이다.
- 원본 NDJSON은 저장용 반출이며 `.sanbo` 전체 복원 입력이 아님을 구분한다.
  파일 저장 실패 때 임시 경로를 성공 메시지로 보여주지 않는다.

## 5. 보관 안내를 실제 동작에 맞춘다

- 전체 백업 사전 안내에 암호화하지 않은 파일이라는 점을 명시한다.
- ‘이 기기에만 저장’ 대신 앱이 기기 안에 기록하고 별도 산보 서버에 동기화하지
  않는다는 점을 설명한다. iOS에는 OS 백업 설정에 따라 포함될 수 있다는 안내를 둔다.
- 실패한 산책은 원본 보존 요청 때문에 이번에 자동 삭제하지 않는다. ‘저장하지
  않았어요’라고 단정하는 메시지는 기록 목록에 넣지 못했고 불확실한 위치 자료는
  기기에 남는다는 내용으로 바로잡는다. 기존 전체 기록 삭제로 함께 지워진다는 점을
  설정 안내에 연결한다.
- 실패 기록만 골라 삭제하는 UI, 보관 기간, iOS OS 백업 제외는 다음 설계의 결정이다.
  이번 수정으로 보관 문제 자체가 모두 해결됐다고 말하지 않는다.

## 비교한 대안

| 대안 | 판단 |
|---|---|
| 기존 picker 뒤의 Dart 크기 검사만 강화 | native 선행 할당을 막지 못해 제외 |
| 모든 백업을 현재 알고리즘으로 다시 계산 | 기존 사용자 결과/라벨을 바꿀 위험 때문에 제외 |
| 클립보드에 민감 표시만 추가 | 구형 Android 접근을 막지 못해 원본은 파일 저장 선택 |
| SQLCipher/서버/계정 도입 | 이번에 확인한 입력 처리 문제를 직접 해결하지 못하고 운영 부담이 커 제외 |
| GPS accuracy 안의 이동을 모두 버리기 | 정상적인 느린 걸음도 잃을 수 있어 별도 측정 설계로 분리 |

## 검증과 완료 조건

- 새 반례를 먼저 회귀 테스트로 옮긴다. 큰 정수/실수, 7일 경계, 천 년 범위, 잘못된
  제외 참조를 거부하고 기존 DB의 5개 테이블 행을 모두 유지하는지 확인한다.
- 정상 v1/v2 백업, 중복 가져오기, 과거 시간대, 부분 분, 제외 취소를 유지한다.
- Android 입력은 크기 누락/거짓 크기/초과/중도 실패/취소/Activity 재생성/늦은 결과를
  검증한다. 한도는 낮게 주입한 가짜 stream으로 대부분 검증하고 실제 최대 크기는
  별도 소유한 QA 기기에서 제한적으로 확인한다. 실제 사용자 파일을 사용하지 않는다.
- 원본 내보내기 취소/실패/완료, clipboard 미사용, 기본 요약에 개인정보 메모가
  포함되지 않음, 작은 화면/큰 글씨 안내를 확인한다.
- 집계 실패와 이상값에도 목록/상세 접근과 개별 삭제가 가능한지 검증한다.
- 변경 관련 테스트를 먼저 통과시킨 후 통합 게이트를 한 번 실행한다. Android/iOS
  native 변경 범위에 맞는 테스트와 기존 backup restore 데이터를 비교한다.
- 구현자는 문서와 코드를 함께 갱신하고 PR에 증거와 남은 위험을 남긴다. 이 문서
  승인은 구현 설계 승인이다. 배포 시에는 완성된 후보와 검증 결과를 제공한다.

## 후속 과제와 구현자 검토

다음 순서는 GPS 흔들림 측정 설계, 실패 기록 보관 정책, iOS 공개 전 OS 백업 결정이다.
현재의 고속 자동 제외와 원본 GPS 보존 정책은 그대로 유지한다. CARTO 키 외부 재사용과
광고 전 상업용 전환도 이전 운영 과제로 남는다.

사용자 지침의 재위임 금지에 따라 별도 subagent builder check 대신 작성자가 구현자
관점으로 다시 읽었다. 과거 기록 보존, 부분 분의 상한, 기존 오염 데이터의 접근 경로,
native 취소 후 파일 정리, iOS 범위의 한계를 본문에 명시했다. 작업 분할, helper 위치,
native 취소 신호의 구체 구현은 구현 계획에서 정한다.
