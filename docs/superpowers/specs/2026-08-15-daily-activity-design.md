# 산보 일별 운동량 설계

작성일: 2026-08-15
대상 기준선: v0.7.1 (`f77b310`)
범위: 기록 화면의 7일 단위 운동량 조회와 로컬 집계 API

## 1. 목표와 성공 기준

사용자가 기록 화면에서 오늘을 포함한 7일의 운동량을 날짜별로 확인하고, 날짜를
선택해 총 거리·총 산책 시간·산책 횟수를 바로 비교할 수 있게 한다.

성공 기준:

- 기록 화면에서 별도 화면 이동 없이 7일치 날짜와 선택일 합계를 확인한다.
- 산책은 `started_at`의 로컬 달력 날짜에 전부 귀속한다.
- 같은 날 여러 산책은 거리·시간·횟수를 합산한다.
- 기록이 없는 날짜도 0값으로 표시한다.
- 오늘 이후 날짜로는 탐색하지 못한다.
- 집계는 SQLite에서 수행하며 전체 세션 목록을 Dart 메모리로 읽지 않는다.
- 기존 전체 누적 카드와 최근 산책 목록의 의미와 동작은 유지한다.

## 2. 사용자 경험

기록 화면의 전체 누적 카드 아래, 최근 산책 목록 위에 `일별 운동량` 패널을 둔다.
패널은 선택된 7일 구간의 시작일과 종료일, 이전·다음 구간 버튼, 일곱 개 날짜 선택
항목, 선택일의 세 지표를 포함한다.

- 최초 진입 시 오늘이 선택되며 구간은 오늘을 마지막 날로 하는 최근 7일이다.
- 각 날짜 항목은 요일과 일자를 표시하고, 선택 상태와 오늘 상태를 색상 외의 형태와
  접근성 레이블로도 구분한다.
- 이전 버튼은 정확히 7일 전 구간으로 이동한다.
- 다음 버튼은 현재 구간을 넘지 않을 때만 활성화하며, 미래 날짜는 표시하지 않는다.
- 선택일 지표는 `거리`, `시간`, `산책` 순서로 표시한다.
- 0값은 빈 화면으로 바꾸지 않고 `0.00 km`, `00:00`, `0회`로 표시한다.
- 날짜 선택은 최근 산책 목록을 필터링하지 않는다. 선택 때문에 기존 기록이
  사라졌다고 오해하지 않도록 목록은 계속 전체 최신순을 유지한다.
- 좁은 화면이나 큰 글씨에서는 세 지표를 세로로 쌓아 overflow를 방지한다.

## 3. 도메인 모델과 저장소 API

새 불변 모델 `DailyWalkStats`는 다음 값을 가진다.

```dart
class DailyWalkStats {
  const DailyWalkStats({
    required this.date,
    required this.walkCount,
    required this.totalDistanceM,
    required this.totalDurationS,
  });

  final DateTime date; // 로컬 자정, 시간 구성요소 없음
  final int walkCount;
  final double totalDistanceM;
  final int totalDurationS;
}
```

`WalkRepository`에 다음 API를 추가한다.

```dart
Future<List<DailyWalkStats>> dailyStats({
  required DateTime startDate,
  required DateTime endDateExclusive,
});
```

API 계약:

- 입력은 로컬 날짜 경계이며 `startDate < endDateExclusive`여야 한다.
- 반환값은 `[startDate, endDateExclusive)`의 모든 날짜를 오름차순으로 포함한다.
- 세션이 없는 날짜도 0값 객체를 반환하므로 UI가 빈 날짜를 따로 합성하지 않는다.
- `status = completed`인 세션만 집계한다.
- 날짜 귀속은 세션 시작일 기준이다. 자정을 넘어 끝난 산책도 시작일에 전부 더한다.
- DB의 `started_at` 범위 조건과 날짜별 `GROUP BY`로 거리·시간·횟수를 집계한다.
- 손상된 음수·비유한 합계는 모델 경계에서 0으로 정규화한다.
- 잘못된 범위는 `ArgumentError`로 거부한다.

기존 DB 스키마와 백업 포맷은 변경하지 않는다. 기존 `sessions.started_at` 인덱스와
완료 상태 조건을 활용하고, 실제 query plan에서 전체 테이블 정렬이 발생하지 않는지
테스트한다.

## 4. 상태와 데이터 흐름

기록 기능에 7일 구간 시작일과 선택일을 보관하는 UI 상태를 둔다. provider는 현재
구간을 저장소 API에 전달하고 `historyTickProvider`를 구독한다. 산책 종료·삭제·백업
가져오기 뒤 history tick이 바뀌면 전체 누적, 최근 목록, 일별 통계가 함께 갱신된다.

흐름:

1. 화면 진입 시 오늘을 로컬 자정으로 정규화한다.
2. 오늘을 마지막으로 하는 7일 범위를 계산한다.
3. 저장소가 7개의 `DailyWalkStats`를 반환한다.
4. UI는 선택일과 일치하는 항목의 세 지표를 표시한다.
5. 날짜 선택은 로컬 상태만 변경하고 추가 DB 조회를 하지 않는다.
6. 주간 이동 때만 새 범위를 조회한다.

화면이 다시 만들어지거나 기록이 갱신돼도 선택일이 현재 범위 안이면 유지한다.
범위를 이동하면 새 구간의 마지막 날을 선택한다.

## 5. 오류와 접근성

- 일별 API 실패는 전체 기록 화면을 가리지 않는다. 일별 패널 안에 짧은 오류 안내와
  `다시 시도` 동작을 표시한다.
- 전체 기록 provider 실패는 기존 화면 수준 오류 처리를 유지한다.
- 날짜 버튼은 최소 48dp 터치 영역과 `8월 15일 금요일, 산책 2회, 선택됨` 형태의
  의미 있는 Semantics 레이블을 제공한다.
- 이전·다음 버튼은 이동할 날짜 범위를 접근성 레이블로 알린다.
- 색상만으로 선택·오늘·비활성 상태를 구분하지 않는다.

## 6. 테스트 전략

저장소 테스트:

- 같은 날 여러 완료 세션의 거리·시간·횟수를 합산한다.
- 진행 중 세션은 제외한다.
- 자정을 넘는 세션은 시작일에 전부 집계한다.
- 범위 안의 기록 없는 날짜도 0값으로 반환한다.
- 시작 포함·종료 제외 경계를 지킨다.
- 잘못된 날짜 범위를 거부한다.
- 집계 쿼리가 완료 세션 시작일 인덱스를 사용한다.

상태·위젯 테스트:

- 최초 화면은 최근 7일과 오늘의 0 또는 실제 합계를 표시한다.
- 날짜를 선택하면 표시 지표만 바뀌고 최근 목록은 유지된다.
- 이전·다음 7일 이동과 미래 이동 제한이 동작한다.
- 일별 API만 실패했을 때 최근 기록은 계속 보인다.
- 좁은 화면과 큰 글씨에서도 overflow가 없다.
- 날짜 버튼의 접근성 레이블과 선택 상태가 정확하다.

전체 회귀 게이트:

- `flutter analyze --no-pub`
- `flutter test --no-pub --concurrency=1`
- `flutter build apk --debug`
