# 산보 배경 지도 복구 설계 초안

상태는 사용자 승인이다. 2026-10-15 사용자가 기존 CARTO 유지 안을 승인하고
진행을 요청했다. 승인된 1차 유지보수 구현 중 실제 화면에서 확인한
M-19/MR-17을 해결하기 위한 추가 범위다. [작성된 구현 계획](../plans/2026-10-15-basemap-service-restoration.md)은 검토 전이며 제품 변경은 아직 없다.

## 확인한 문제

`lib/shared/widgets/route_map.dart`는 키 없이 CARTO Voyager raster URL을 호출한다.
2026-10-14 iOS 26.5 전용 시뮬레이터에서 상세 지도의 배경이
`API KEY REQUIRED`로 표시됐다. 동일 공급자의
`https://a.basemaps.cartocdn.com/rastertiles/voyager/14/13971/6348.png`를
조회했을 때 HTTP200, image/png, 2049bytes였으며 파일을 직접 열어 같은 안내
이미지임을 확인했다. 이 테스트 좌표는 합성 위치다.

[CARTO 공식 문서](https://docs.carto.com/faqs/carto-basemaps#why-do-i-see-an-api-key-required-watermark)에
따르면 2026-09-25부터 usable API key 없는 raster 요청에는 지도를 제공하지
않는다. 키가 필요한 현재 계약과 인증 없는 앱 URL이 맞지 않는다.
측정/저장/재생 경로 좌표는 남아 있으나 도로와 지명을 볼 수 없다.

## 접근 비교

| 접근 | 장점 | 조건과 한계 |
|---|---|---|
| 기존 CARTO에 전용 basemap 키 연결, 추천 | 지도 스타일/출처/현재 개인정보 안내 유지, 변경 범위가 작음 | 사용자 소유 키 준비, 공개 모바일 클라이언트 사용 범위와 월 사용량 확인 필요 |
| 키 없는 다른 지도 공급자로 변경 | CARTO 키 발급에 의존하지 않음 | 해당 공급자의 모바일 사용/캐시/요청 제한을 먼저 검토하고 스타일/출처/개인정보 안내와 검증을 함께 변경해야 함 |
| 배경 지도를 끄고 경로만 표시 | 외부 장애와 관계없이 기록과 재생을 볼 수 있음 | 도로와 지명을 복구하지 못하므로 오류 시 임시 표시로만 사용 |

CARTO는 계정 없이 basemap 키를 요청할 수 있고 사용 유형별 무료 요청 한도를
제공한다. [공식 요금과 키 안내](https://docs.carto.com/faqs/carto-basemaps#what-is-the-pricing-for-carto-basemaps-is-it-free)를
기준으로 사용자가 사용 유형을 정하고 직접 발급한다. 이 설계는 결제/약관 동의나
새 계정 생성의 승인을 포함하지 않는다. 키를 대화나 Git에 붙여 넣지 않는다.

## 추천안의 구현 경계

- 기존 `RouteMap`과 raster renderer를 유지한다. 공급자 추상화나 지도 엔진
  교체를 도입하지 않는다.
- 빌드 환경의 `CARTO_BASEMAP_KEY`를 Dart define으로 전달하고, 키가 있으면
  기존 URL에 URL-encoded `key` query를 붙인다. 키가 담긴 전체 URL을 로그에
  남기지 않는다. 모바일 앱에 들어가는 키는 앱에서 추출 가능하므로 서버 비밀
  자격 증명으로 취급하지 않고 basemap 용도로만 제한한다.
- 키가 없으면 인증 없는 외부 요청을 반복하지 않는다. 기존 경로 preview 위에
  `배경 지도를 불러올 수 없어요. 산책 경로와 기록은 그대로 볼 수 있어요.`를
  표시한다. 구현 설정명을 사용자 문구에 노출하지 않는다.
- 인증/네트워크 오류에서도 원본 경로, 선택 구간과 재생 cursor를 유지한다.
  무한 재시도나 공급자 자동 전환을 넣지 않는다.
- 신규 signed build의 release gate는 키 준비 여부를 확인한다. 실제 지도의
  도로/지명 렌더링을 Android/iOS에서 확인해야 통과다. HTTP200이나 이미지
  decode 성공을 정상 지도 확인으로 대체하지 않는다.
- SQLite/백업/export/거리 계산/기존 v0.9.1은 변경하지 않는다. 승인 후 변경한
  제품 build SHA로 후보를 다시 빌드하고 draft 자산과 증적을 갱신한다.

## 수용 기준

1. 준비한 키로 기존 Voyager 도로와 지명이 실제 Android/iOS 상세 화면에 보인다.
2. 키 미설정과 인증 실패, 오프라인에서도 경로/재생/기록을 볼 수 있고 상태 안내가
   보인다. 보이지 않는 배경을 정상 지도로 안내하지 않는다.
3. 저장소/PR/릴리즈 로그와 문서에 실제 키가 없다. 설정/출처 문구가 실제 공급자와
   일치한다.
4. 전체 품질 gate와 실제 백업/기존 설치 업데이트 수용 기준을 변경한 소스에 맞춰
   적용한다. 제품 변경 없는 native gate는 필요한 회귀가 없으면 반복하지 않는다.

2026-10-15 합성 invalid 키로도 HTTP200/동일2049bytes PNG가 반환됐고 ETag는
`"wm-da89c20e77c1-light"`였다. 구현 계획에는 이 확인된 안내 응답을 인증 실패로
다루는 경계와 실제 정상 지도 확인을 넣었다. 빌드 환경에서 키가 준비됐는지만
확인했으며 현재 `CARTO_BASEMAP_KEY`는 없다. 키 값을 조회/출력한 것은 아니다.
