# 고속 자동 제외 비판적 검토

검토일은 2026-10-16, 최초 대상은 PR #2의 `4297d1a7acf2f088a205b8ef498c4304e035e062`다.
사용자가 요청한 다방면 검토를 직접 수행했다. 별도 검토자나 물리 기기의 검증으로 주장하지 않는다.
기존 head의 Flutter/Android CI와 native CI 성공은 GitHub에서 확인했다.

## 발견한 오류와 수정

### R1, P1, 완료 재시도가 제외와 사용자 수정을 덮어씀

동일한 120초/360m 입력으로 finalizeSession을 두 번 호출하거나 동시에 호출하면
같은 시간 범위의 제외가 2개 생겼다. 취소 후 메모와 걷기 라벨을 저장한 뒤 오래된
완료 요청을 다시 보내면 제외를 다시 만들고 메타데이터도 덮어썼다.
discarded 세션도 완료 상태로 되살릴 수 있었다.

완료 transaction 안에서 현재 세션을 읽고, 이미 완료된 기록은 쓰기 없이 그대로 반환한다.
active인 경우만 최초 완료를 허용하고, 현재 저장된 세션 메타데이터를 사용한다.
samples와 windows의 행 ID 및 제외 ID도 재시도 전후 동일하게 유지됨을 확인했다.

### R2, P1, 기존 제외와 세션 집계가 어긋나는 완료 API

전체 120초가 자동 제외된 세션에 completeSession을 다시 호출하면 제외는 유지하면서
집계만 360m/120초로 덮어썼다. 지도와 거리/시간이 서로 다른 원인을 확인했다.
동일한 transaction 상태 확인으로 이미 완료한 집계도 보존하도록 수정했다.

### R3, P2, 과거 형식의 시각 키로 차량을 확정하면 제외 누락

서울의 `18:00` 또는 뉴욕의 `05:00`으로 저장한 offset 없는 과거 분 키를 편집하면
차량 라벨은 저장됐지만 제외 후보는 없었다. 수정 helper는 실제 행을 찾았으나,
후속 후보 선택이 요청 시각을 UTC로 다시 해석해 다른 분을 찾는 것이 원인이었다.

helper가 실제 수정한 저장 키를 반환하고, 세션 시간대로 해석한 그 키만 제외 후보로 쓴다.
서울/뉴욕과 단일/일괄 편집의 네 경우 모두 실제 UTC 09:00~09:01만 제외하며 원본 행을 보존했다.

## R4, P1, 제외 경계에서 정상 산책 선분 손실

R4, P1. 1m/s로 60초간 60m 걷고 이어서 3m/s로 60초 이동한 합성 기록에서,
뒤의 60초만 자동 제외했지만 정상 산책 거리도 줄었다.

| GPS 간격 | 제외 후 유효 시간 | 남은 이동 시간 | 남은 거리 | 보존할 정상 거리 |
|---|---:|---:|---:|---:|
| 4초 | 60초 | 56초 | 56m | 60m |
| 20초 | 60초 | 40초 | 40m | 60m |

RoutePartitioner가 제외 시작 시각의 실제 GPS 좌표도 버려 앞쪽 마지막 선분이 사라진다.
이 동작은 이번 속도 정책 변경 전부터 존재했고 기존 테스트에도 계약으로 고정돼 있었다.
사용자가 2026-10-16 같은 PR에서 경계 선분을 보존하는 범위를 승인했다.

제외 시작 시각과 정확히 같은 실제 좌표를 앞쪽 포함 fragment의 끝점으로만 쓰고
즉시 경로를 닫도록 수정했다. `includedSamples`의 반개구간 소속, 제외 범위와 시간은
유지한다. 제외 내부로 이어 붙이거나 새 좌표를 보간하지 않으며, 필터 거부/무효 좌표/
관측 공백/인접 제외도 기존 연결 차단을 유지한다. 구간 선택 지도에서도 같은 끝점을 보존한다.
수정 뒤 두 GPS 간격 모두 정상 거리 60m, 이동 시간 60초, 유효 시간 60초, 평균 1m/s다.

기존 기록까지 일괄 적용하면 과거 저장 거리와 새 지도 경로가 달라지므로, 새로 계산한
제외 분의 evidence에 `distance_window:exclusion_start_endpoint`를 남긴다. 상세 지도와
재생은 근거 없는 과거 기록에 저장 당시 경계를 적용하며 숨은 쓰기를 하지 않는다.
근거는 기존 백업 schema 2에서 왕복하고, JSON/NDJSON export에도 포함한다.
명시적 제외/복원은 집계와 분 근거를 원자적으로 갱신한다. 실제 지원하는 export는
JSON, NDJSON과 텍스트 요약이며 CSV 구현은 없다.

## 다방면 확인과 검증

- 새 회귀는 기존 코드에서 8건 실패를 확인했고, 폐기 기록 완료 거부도 2건 실패를 확인했다.
  수정 후 새 10건과 기존 저장소/백업/자동 제외 테스트를 합친 80건이 통과했다.
- R1~3 수정 단계의 `flutter test --no-pub --concurrency=1 --reporter expanded`는 559개 통과했다.
  `flutter analyze --no-pub`는 이슈가 없었다.
- PRD/TRD 구조 검사, 변경 Dart 파일 format과 diff 검사, Android debug APK 빌드도 통과했다.
  기존 health 플러그인의 KGP 전환 경고는 남으며, 지도 키 없는 개발용 빌드다.
- 5시간/4초 간격의 GPS 4,501개와 분 300개를 사용한 별도 probe에서 한 범위로 정확히 병합했다.
  개발 호스트에서 pipeline 86.734ms, 정책 판단 6.886ms였다. 단일 실행이며 휴대폰 성능 주장이 아니다.
- 10km/h/30초/25m/30초 간격 경계, 원본 보존, 확정 라벨 우선과 취소 유지의 기존 테스트도 통과했다.
- UI는 추정임과 제외 취소를 안내한다. 320px/글자 크기 2배 테스트와 복원 semantics 회귀를 유지했다.
  undo 전용 스킬 검색은 관련 없는 결과여서 채택하지 않았고, 실제 동작과 일반 UX 기준으로 검토했다.
  Flutter 접근성 검색 결과의 큰 글자/semantics 지침은 기존 위젯 테스트와 대조했다.
- VoiceOver/TalkBack 실사용, 물리 GPS 정확도, 배터리, 모든 크기/가로 화면의 대비는 실측하지 않았다.
  새 자동 제외 임계값의 실제 발생률도 합성 fixture만으로 보장하지 않는다.
- MR-08의 원본 거리 노이즈 보정과 MR-15의 레거시 부분 제외 표시 문제는 별도 범위로 남는다.
  단일 15m 급증을 자동 제외하지 않게 했지만 원본 거리 92.4m 자체를 보정한 것은 아니다.

로그와 진단 probe는 로컬 `.superpowers/sdd/2026-10-16-high-speed-critical-review/`에 보관한다.
새 schema, 외부 서비스, 지도 키, native 코드와 공개 릴리즈 자산은 변경하지 않았다.

## 경계 보존 후속 검증

- 수정 전 도메인/저장소 회귀에서 정상 끝점 손실 4건, 화면 회귀에서 새 경로 끝점 손실
  1건을 재현했다. 필터, 무효 좌표, 공백, 보간 금지와 과거 경계 유지도 함께 검사했다.
- 수정 후 관련 도메인/저장소/상세 화면 42개가 통과했다. 4초/20초 간격에서 정상
  60m/60초를 유지하며, 세션/분/기록 목록/누적/일별 집계가 일치했다.
- 지도 전체와 구간 선택, fragment를 보존한 재생, JSON/NDJSON/텍스트 요약,
  schema 2 백업 왕복, 제외 취소 후 240m/120초와 원본 행 보존을 검증했다.
- 근거 있는 새 기록은 경계 좌표까지, 근거 없는 과거 기록은 이전 끝점까지만 표시한다.
  각 기록에서 상세 조회와 구간 선택 전후의 백업이 같아 숨은 쓰기가 없음을 확인했다.
- 최신 전체 테스트는 570개 통과했고 `flutter analyze --no-pub`는 이슈가 없었다.
  변경 Dart 파일 10개의 format 검사, PRD/TRD 구조 검사와 diff 검사도 통과했다.
- Android debug APK 빌드가 성공했다. SHA-256은
  `7489a333681f818423677eb09170dade6afd8793be998e5b200713d02fcff5b9`다.
  기존 health 플러그인의 KGP 전환 경고가 남으며 지도 키 없는 개발용 산출물이다.
