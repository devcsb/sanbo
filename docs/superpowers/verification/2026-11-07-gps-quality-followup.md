# GPS 신뢰도 후속 검증

2026-11-07, 기준 `25e6599`, 작업 브랜치 `codex/gps-quality-followup`.
사용자는 S26 연결과 실측을 나중으로 미루고 연결 없이 할 수 있는 작업을 진행하라고 했다.
[설계](../specs/2026-11-07-gps-quality-followup-design.md)와
[계획](../plans/2026-11-07-gps-quality-followup.md)에 따라 직접 구현했다.
연결 없이 수행하는 이번 범위의 구현과 검증을 완료했다. 실기기 실측은 사용자 요청대로 보류했다.

## 변경과 보존 경계

GPS 정확도 안에서 반복 왕복하는 분에 확인 evidence를 붙이고 활동을 낮은 확신으로
표시한다. 완료 상세와 구간에 확인 안내를 제공한다. 원본 GPS, 거리, 이동 시간과
평균 속도를 자동으로 지우거나 보정하지 않는다. 동일한 좌표가 실제 짧은 왕복일 수
있기 때문이다. 사용자가 확인했거나 제외한 구간에는 안내를 반복하지 않는다.

신규 DB 열, 백업 버전, 패키지, 네트워크 진단과 timer를 추가하지 않았다. 기존 처리
시점의 분 집계와 evidence 저장을 재사용한다. 과거 DB를 읽으면서 숨은 재계산을 하지 않는다.
고속 자동 제외, 위치 요청 간격, Samsung provider 복구와 WakeLock은 유지한다.

경로 분할의 전체 제외 반복 스캔은 정렬 뒤 두 전진 커서로 바꿨다. 포함 여부와
선분 교차를 각각 추적하므로 이미 지난 제외를 다시 스캔하지 않는다. 경계 선분,
반열린 제외 범위와 긴 공백/필터의 단절 결과는 그대로다.

## 실제 반례와 검사

| 검사 | 관찰 |
|---|---|
| 왕복 6좌표, accuracy 30m, provider speed 0 | 약 100m와 이동 50초가 기존처럼 보존된다. 추가로 확인 evidence와 확신 0.25의 unknown을 남긴다. |
| 감지 연결을 되돌린 mutation | 기대한 evidence 대신 기존 speed_band/stationary_ratio만 남아 회귀가 실패했다. 원복 후 통과했다. |
| 선형 검사 예산 | 이전 구현 199,000회로 상한 4,400회를 위반. 새 구현은 통과. 실행 시간에 의존하는 테스트가 아니다. |
| 이전 구현과 결과 비교 | 고정 seed 300입력 × 경계 옵션 2개, 추가 중복/인접 제외/무효 좌표/세션 경계에서 포함 좌표, fragment와 선분 거리 일치 |
| 정상 이동 | 느린 직선, 원형과 단일 반전은 미표시. 양수 속도나 정확한 왕복도 과잉 표시하지 않음 |
| GPS 한계 | 실제 짧은 왕복과 같은 GPS는 확인 대상으로 남는다. 이를 자동 삭제하는 테스트를 만들지 않음 |
| 이상 입력 | 적은 표본, 짧은 관측, 30초 초과 공백, NaN/누락/0/과도한 정확도, 중복 시각, 무효 좌표와 날짜 변경선 |
| 필터 경계 | 중간 거부 좌표가 있는 분을 이어 붙여 판단하지 않음 |
| 저장과 복원 | 원본 좌표/필터 표시, 메모, 확정 라벨과 거리/이동 시간을 보존. evidence가 백업과 NDJSON에 유지됨 |
| 제외와 취소 | 사용자 확정 뒤 제외/취소해도 원본 수치와 확정 메모를 유지하고 안내를 반복하지 않음 |
| 제품 UI | 미확정/확정/제외/기존 고속 안내 조합, 320px/200% 글자, 다크, 동작 줄이기, 48px 구간 이동 |
| 지도 출처 표시 | 최종 200% 캡처에서 발견한 기존 잘림을 재현: 오른쪽 경계 530px 기대, 실제 800.5px. 좌우 폭 제약과 줄바꿈으로 수정하고 글자 배율은 유지 |

새 기능의 첫 RED에는 존재하지 않는 테스트 enum 이름도 섞여 있었다. 이를 현재
`SessionStatus.active`로 고치고, 이후 실제 evidence 연결을 제거한 mutation으로
행동 실패를 따로 확인했다. UI 테스트도 실제 제목 ‘활동 흐름’으로 수정했다. 이
harness 오류를 제품 결함으로 보고하지 않는다. 첫 UI RED는 안내와 사람이 읽는
부제가 없어서 실패했으며 구현 뒤 통과했다.

## 계산 비용 비교

다음 명령은 합성 입력만 사용하며 이전 구현을 테스트 참고 파일로 함께 실행한다.
초회는 버리고 실행 순서를 교차한 3회 중앙값이다. 반환 거리와 개수도 대조한다.

```sh
dart run scripts/benchmark_route_partition.dart
```

| 좌표/제외 수 | 이전 | 현재 |
|---|---|---|
| 각각 1,000개 | 14.10ms | 1.01ms |
| 각각 3,000개 | 119.20ms | 1.07ms |

로그는 `build/gps-route-benchmark.log`다. 이 로컬 Dart 실행의 특정 입력 결과이며
S26에서의 latency/배터리 절감률이나 센서 정확도 결과가 아니다. 제거한 것은
반복 계산이며 새로운 GPS 수신 정책을 검증한 것이 아니다.

## 화면과 문서

기존 고속 안내와 같은 패널을 쓰며 버튼도 재사용한다. 불확실성에 맞게 GPS 아이콘과
짧은 문구를 사용하고 새 bitmap 에셋은 만들지 않았다. 두 테마의 320px/200% 합성
이미지를 `build/gps-review-{light,dark}.png`로 렌더링해 확인했다. 추가로 지도 출처의
잘림을 고치면서 원래 출처 문구와 글자 배율을 유지했다. 기계용 evidence는
화면에 노출하지 않는다.

PRD/TRD를 구현과 맞췄다. 과거 TRD의 8m 반경 정지 규칙이 현재 구현에는 없는 것도
명확히 했다. [S26 실측 절차](../../testing/2026-11-07-s26-location-energy.md)는
OS 버전을 추측하지 않고 실제 APK/OS/화면/충전 조건을 기록하며 누적 통계의 차이를
비교한다. 앱/배터리 통계 삭제와 전체 위치 로그의 외부 전송은 필요하지 않다.

[CARTO 운영 문서](../../security/carto-operations.md)에는 공식 FAQ 재확인과 공개
헤더의 한계, 서버 검증과 사용량 제한을 설계할 때 필요한 경계를 추가했다. 계정의
현재 설정과 초과 청구 조건, 제한 키의 공격 대조를 확인한 것으로 표현하지 않는다.

## 최종 게이트

최종 지도 출처 수정까지 포함해 아래 명령을 실행했다. 실행 중 소스 변경 없이
종료 코드 0과 완료 문구, 새 APK와 `[quality] PASS`를 확인했다.

```sh
env -u CARTO_BASEMAP_KEY bash scripts/run_quality_loop.sh --debug-apk
```

| 검사 | 결과 |
|---|---|
| PRD/TRD 구조 | PASS |
| Python 도구 검사 | 21개 통과 |
| Dart 정적 분석 | No issues found |
| Flutter 전체 회귀 | 655개 통과, 1분 24초 |
| Android debug APK | assembleDebug 9.3초, APK 생성 |
| 소스 일관성과 공백 | PASS |
| GPS/저장/화면 집중 검사 | 18개 통과 |
| 지도와 GPS UI 회귀 | 23개 통과 |
| 최종 합성 화면 | 2개 통과, light/dark 이미지 직접 확인 |

집중 검사에는 중복되는 테스트가 있으며 전체 개수에 더하지 않는다. 최종 전체 로그는
`build/gps-followup-quality-final.log`다. 초기 전체 게이트 654개 통과 뒤 지도 출처
잘림을 발견했고, 회귀 1개를 추가해 실제 RED를 확인한 후 최종 전체를 실행했다.

주요 증거는 `build/gps-followup-red.log`, `gps-marker-mutation-red.log`,
`gps-marker-final-green.log`, `gps-followup-focused-final.log`, `gps-map-attribution-{red,green}.log`,
`gps-review-capture-verified.log`다. 자료는 Git에서 제외한 로컬 `build/`에 있다.

네이티브 소스 변경은 없으며 native 테스트를 다시 실행한 것으로 표현하지 않는다.
새 debug APK는 CARTO 키를 전달하지 않은 검증용이다. 공개 release/지도 인증이나
실기기 배터리 검증의 증거가 아니다. SHA-256은
`7f18b7ac5c48e9623b11123482706cd39be16f6007587f56a4f624998079f878`이다.

문서 완료 상태 갱신 뒤에는 문서 구조와 공백만 다시 확인한다. 제품 소스의 최종
검사는 위 전체 게이트이며 통과한 같은 검사를 불필요하게 반복하지 않는다.

## 남은 한계

이 단계는 GPS 잡음의 자동 보정을 완성한 것이 아니다. 지하철 혼입의 초 단위 전환,
단방향 드리프트, sparse 표본과 속도 누락은 실측과 추가 설계가 필요하다. 경고가
없다는 것이 정확한 거리라는 뜻도 아니다. 사용자의 실제 짧은 산책을 지우는 기준을
실측 없이 만들지 않았다.

S26 실측은 사용자 요청으로 보류했다. 배터리 절감률과 실제 GPS 성능을 보고하지
않는다. CARTO 키 추출/외부 재사용을 이 클라이언트 변경으로 해결하지 않았으며
기존 키, 계정, 요금제와 공개 release를 변경하지 않았다. 별도 독립 모델이나 보안
업체의 검토를 수행한 것으로 표현하지 않고 코드/반례/원본 보존/기존 구현을 대조했다.
