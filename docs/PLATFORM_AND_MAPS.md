## 2. 왜 Flutter인가

### 2.1 요구와의 정합

| 요구 | Flutter 적합성 |
|------|----------------|
| Android 먼저 | 1차 타깃 빌드·권한·포그라운드 서비스를 Android에서 검증 가능 |
| 이후 iOS | 동일 Dart 파이프라인(분 윈도우·추측) 재사용; UI·권한 어댑터만 분기 |
| 개인 사이드 프로젝트 | 네이티브 이중 구현 비용 대비 생산성 유리 |
| 지도 폴리라인·리스트 UI | Flutter 생태계 충분 (`maplibre_gl` / `flutter_map`, `geolocator`, `sqflite` 등) |

### 2.2 의식적으로 감수하는 리스크

| 리스크 | 완화 |
|--------|------|
| 백그라운드 위치의 플랫폼 특수성 | `LocationEngine` 어댑터 분리(TRD). Android: FGS+알림 정석. iOS는 later 전용 절 |
| 일부 한국 맵 공식 Flutter SDK 성숙도 편차 | **맵을 “타일+오버레이” 추상화**해 SDK 교체 가능하게 설계 |
| 앱 용량 | MapLibre 네이티브 엔진 포함 시 용량↑ → 불필요 플러그인 최소화 |

### 2.3 기각 대안

| 대안 | 기각 이유 |
|------|-----------|
| Android 네이티브 only | iOS 이전 시 전면 재작성 |
| React Native | 가능하나 팀 선호·생태계 차이; 본 프로젝트는 Flutter 고정 |
| Kotlin Multiplatform UI | 러닝 커브 대비 사이드 프로젝트 ROI 낮음 |

**결정 D-PLAT-01**: 클라이언트는 **Flutter**. 패키지/모듈 구조는 `android` 타깃 우선 완성.

## 3. Android 우선 · iOS 후속

### 3.1 단계

```
Phase A (MVP): Android only
  - 권한 · Foreground Service · 배터리 모드
  - 지도 폴리라인 · 분 타임라인 · 로컬 DB
Phase B: iOS 포트
  - 권한 문구 · Background Modes
  - 동일 순수 Dart 파이프라인 재사용
```

### 3.2 Android MVP에서 반드시 닫을 것

1. `ACCESS_FINE_LOCATION` + (백그라운드 시) 단계적 권한 UX  
2. **Foreground Service** (`location` 타입) + 고정 알림(“산책 기록 중”)  
3. 배터리 최적화 **강요 금지**, 안내만  
4. 프로세스 킬 후 `active` 세션 복구  

### 3.3 iOS later 체크리스트 (구현 시)

- When In Use → Always 교육 화면  
- `UIBackgroundModes: location`  
- 백그라운드 인디케이터(파란 바) 사용자 기대 관리  

**결정 D-PLAT-02**: 스토어/배포 검증은 Android 먼저. iOS 코드 경로는 컴파일 가능 수준만 유지해도 MVP 합격(필수 아님).

## 4. “대한민국 공개 지도” 심층 분석

사용자가 말한 **공개된 지도**는 해석이 둘 있다. 둘 다 검토한 뒤 레이어 전략으로 합친다.

| 해석 | 의미 | 대표 소스 |
|------|------|-----------|
| **A. 공공·오픈플랫폼** | 국가가 개방한 공간정보 | **브이월드(VWorld)**, 공공데이터포털 연계 API |
| **B. 오픈데이터/오픈소스 지도** | 무료·재사용 가능한 지도 데이터·타일 | **OpenStreetMap(OSM)**, MapLibre 렌더러 |

상용(카카오·네이버·구글)은 국내 UX·POI 품질이 뛰어나지만 **“공개 지도 기반”** 서사·비용·약관 종속 면에서 MVP 기본 경로로는 부적합할 수 있다. **선택적 보조**(역지오코딩)로만 허용.

### 4.1 후보 비교

| 후보 | 공개성 | 한국 지명/도로 품질 | Flutter 구현성 | 비용·키 | 폴리라인 오버레이 | 평가 |
|------|--------|---------------------|----------------|---------|-------------------|------|
| **VWorld (브이월드)** | 국가 공간정보 오픈플랫폼 | 국내 행정·지적·공식 베이스에 강함 | 웹/타일·REST 중심; 모바일은 타일 URL + MapLibre 패턴 또는 공식 모바일 API 문서 따름 | 개발자 키 발급, 트래픽 정책 준수 | 가능(타일 위 라인) | **공공성 최고** — v1 권장 연동 |
| **OSM + MapLibre / flutter_map** | 오픈 라이선스(타일 제공자 ToS 별도) | 도심 양호, POI·최신 상호는 편차 | **Flutter에서 가장 단순·성숙** | 키 없이 가능(타일 정책 준수) | 매우 쉬움 | **MVP 기본 베이스맵 최적** |
| 카카오맵 SDK | 민간 플랫폼 (무료 한도) | 국내 최고 수준에 가까움 | `kakao_map_sdk` 등 플러그인 존재 | 키·앱키 해시·약관 | 지원 | 공개 지도 서사와 불일치 → **POI/검색 보조 후보** |
| 네이버맵 | 민간 | 국내 최고 수준 | 플러그인·설정 복잡도 | 키·콘솔 | 지원 | 동일 — MVP 비기본 |
| Google Maps | 민간·유료 과금 | 글로벌 강, 국내 표기는 경쟁 | 공식 Flutter 패키지 | 결제 계정 필수 | 지원 | **기각(MVP)** 비용·공개 서사 |
| 국토부 2D/벡터 API (data.go.kr 연계) | 공공 | 고품질 가능 | 문서·할당 확인 필요 | 신청 | 가능 | VWorld 계열과 함께 **v1 검토** |

### 4.2 레퍼런스(Codex 스크린샷)와의 연결

영감 이미지는 **OpenStreetMap 계열 타일 위 파란 폴리라인 + 요약 카드**다.  
→ 산보 MVP UX를 동일 패턴으로 가져가면 **구현 단순 + 사용자 익숙** (러닝 앱 결과 화면과 같은 골격).

### 4.3 채택 아키텍처: “렌더러 1개 + 타일 소스 N개”

```
┌─────────────────────────────────────┐
│  MapViewPort (추상)                  │
│   - setCamera, addPolyline, markers │
│   - setTileSource(sourceId)         │
└──────────────┬──────────────────────┘
               │ MapLibre (권장) 또는 flutter_map
     ┌─────────┴─────────┐
     ▼                   ▼
  tile: osm_public    tile: vworld_2d
  (MVP default)       (키 있으면 전환)
```

**결정 D-MAP-01**: 지도 **렌더러 = MapLibre GL Flutter 플러그인** (벡터/래스터 타일·폴리라인·마커).  
**결정 D-MAP-02**: 제품 기본 타일 = **공개 OSM 호환 타일**(Carto Voyager) + 화면 코너 **© OpenStreetMap · © CARTO** 표기. **API 키 없음.**  
**결정 D-MAP-03**: **브이월드(VWorld) 베이스맵 연동은 제품 범위에서 제외** (키·쿼터·약관·배포 복잡도 대비 OSM만으로 충분). 검색/역지오코딩이 필요해지면 별도 검토.  
**결정 D-MAP-04**: 카카오/네이버 **맵 SDK는 MVP 비포함**. 한국어 상호·주소가 꼭 필요해지면 **REST 역지오코딩만** 검토 (맵 렌더와 분리).

### 4.4 브이월드(VWorld) — 비교만 (연동 안 함)

- 포털: [vworld.kr](https://www.vworld.kr/) — 국가 공간정보 개방·2D/3D·OpenAPI.  
- 산보 **현재 구현**: 베이스맵은 **OSM만**. VWorld 키 UI·타일 URL 없음.  
- 제외 사유: 운영키·일일 호출 제한·키 유출(클라이언트 내장)·사용자 공통 쿼터 부담.  
- 향후 필요 시: 검색/역지오코딩 REST만 최소 연동을 재검토할 수 있음 (맵 렌더는 OSM 유지 권장).

### 4.5 역지오코딩·장소 (가벼운 범위)

| 단계 | 전략 |
|------|------|
| MVP | 체류 시에만 시도. 실패 → `장소 미확인` + 좌표. **네트워크 없이도 기록·맵(캐시 타일 범위 내) 동작** |
| 1순위 공공 | VWorld 검색/지오코딩류 API (키·쿼터 확인 후) |
| 대안 | 카카오 로컬 REST (국내 상호 품질↑, 민간·키 필요) — 맵 SDK 없이 REST만 |
| 금지(MVP) | 모든 샘플마다 역지오코딩 (배터리·프라이버시·쿼터) |

**결정 D-MAP-05**: 장소 API는 **배치·체류 트리거·캐시(좌표 반올림)** 만. 파이프라인은 TRD PlaceResolver.

### 4.6 좌표계

- 내부 저장: **WGS84 (EPSG:4326)** lat/lon — GPS·Haversine 표준.  
- VWorld 등 일부 API가 다른 투영을 쓰면 **경계에서만 변환**, DB에는 WGS84 유지.

## 5. 심플 제품 원칙 — 러닝 앱에서 “핵심만”

### 5.1 가져올 것 (Borrow)

실제 러닝/워크 앱(Strava lite 감각, Nike Run Club 시작 화면, Samsung Health 워크 카드, Codex 결과 화면)에서 **반복되는 최소 골격**:

| # | 차용 기능 | 산보에서의 형태 | 의도적으로 버리는 변형 |
|---|-----------|-----------------|------------------------|
| 1 | **큰 시작/종료 버튼** | 홈 중앙 `산책 시작` / `종료` | 목표 km·페이스 알람 |
| 2 | **진행 중 숫자 3개** | 시간 · 거리 · 현재/평균 속도 | 랩, 고도, 케이던스, 심박 |
| 3 | **종료 후 맵 + 요약 카드** | 폴리라인 + 거리/시간/정지/유효 포인트 | 1km 스플릿 표 전체, 트로피 |
| 4 | **기록 목록** | 날짜·거리·시간 리스트 → 상세 | 연간 히트맵·클럽 피드 |
| 5 | **권한·기록 중 알림** | 시스템 정석 한 줄 | 마케팅 푸시 |

산보 **고유 추가**(차별, 그러나 UI는 한 탭 안):

| # | 고유 | 심플 표현 |
|---|------|-----------|
| 6 | 분 단위 타임라인 | 상세 화면 하단 리스트: `14:03 · 걷기 · 72m · 한강공원?` |
| 7 | 활동 가설 수정 | 행 탭 → 칩 선택 (걷기/체류/기타) — 폼 과다 금지 |

### 5.2 가져오지 않을 것 (Reject)

- 소셜·공유 기본값, 리더보드, 챌린지  
- 훈련 계획, 코치 음성, 오디오 큐  
- 신발/장비, 칼로리 강조, 체중 연동  
- 상시(하루 종일) 라이프로그  
- 복잡한 대시보드 위젯 다수  
- 계정·클라우드 동기 (MVP)

### 5.3 정보 구조 (IA) — 화면 3+α

```
[홈]  시작 버튼 + 오늘/최근 1줄
  ├─ (기록 중) 라이브: 시간·거리·속도 + 미니맵(옵션, 꺼도 됨)
  └─ 종료 → [세션 요약] 맵 + 카드 + “타임라인”
[기록] 세션 리스트
[설정] 추적 모드(균형/절전/고정확) · 지도 출처 · 데이터 삭제 · 권한
```

**결정 D-UX-01**: 하단 탭 **최대 3개** (홈 / 기록 / 설정).  
**결정 D-UX-02**: 카피·아이콘은 한국어 1차, 과한 일러스트·온보딩 스텝 ≤ 2.  
**결정 D-UX-03**: 활동 추측 UI 문구는 항상 **「추정」** — 러닝 앱의 “확정 페이스” 톤 금지.

### 5.4 MVP 기능 컷 리스트 (심플 게이트)

아래를 만족하지 못하면 기능 추가 금지:

1. 시작 후 **10초 안에** 기록 중 상태로 들어가는가?  
2. 종료 후 **한 화면**에서 맵+숫자가 보이는가?  
3. “그때 뭐 했지?”가 **타임라인 스크롤**로 해결되는가?  
4. 서버 없이도 **삭제·재설치 전 데이터 의미**가 설명되는가?

## 6. Flutter 모듈 경계 (가벼운 구조)

사이드 프로젝트용 **얇은 레이어**. 과도한 clean-arch 폴더 금지.

```
lib/
  app/           # Material 3, routes, theme (라이트·다크 단순)
  features/
    session/     # start/stop, live UI
    timeline/    # minute list, edit label
    history/     # list + detail map
    settings/
  domain/        # pure: filter, window, metrics, infer (테스트 가능)
  data/          # sqflite, export
  platform/      # location, background, geocoder adapters
  map/           # MapPort + OSM tile (flutter_map RouteMap)
```

**결정 D-ARCH-01**: `domain/` 은 Flutter 위젯·플러그인 import 금지 → 단위 테스트 용이.  
**결정 D-ARCH-02**: 맵·위치는 인터페이스 뒤 — iOS·타일 교체 시 UI 무수정.

### 6.1 권장 패키지 방향 (고정이 아닌 가이드)

| 역할 | 방향 | 비고 |
|------|------|------|
| 위치 | `geolocator` 또는 동등 + Android FGS 설정 | 백그라운드는 추가 설정 필수 |
| DB | `sqflite` / `drift` | MVP는 sqflite로 충분 |
| 맵 | `maplibre_gl` (또는 유지보수 활발한 MapLibre 계열) | 타일 소스 교체 |
| 상태 | `riverpod` 또는 `provider` 중 **하나** | 둘 다 쓰지 말 것 |
| 경로 | go_router 최소 | 탭+상세 정도 |

Google Maps 패키지·Firebase 기본 탑재는 **하지 않음** (가벼움).
