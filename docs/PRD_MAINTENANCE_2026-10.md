## 1. 사용자 요청과 제품 목적

사용자는 과거 개발 내용의 미배포 여부를 확인하고, 배포가 끝났다면 속도 계산과
위치 측정, 오류, UI/UX, 한국어 문구를 비판적으로 검토해 개선하기를 요청했다.
산보의 기존 목적은 산책 중 이동과 체류를 기록하고 나중에 시간대별로 회상하는
개인 로그다. 운동 기록 경쟁, 계정, 서버 수집은 이번 개선에 넣지 않는다.

성공 기준은 다음과 같다.

- 같은 원본 좌표를 복구하거나 완료해도 거리의 근거가 달라지지 않는다.
- GPS가 끊기면 마지막 속도를 현재 속도로 오인하지 않는다.
- 기록을 앱 밖으로 백업하고 다시 가져올 수 있다.
- 숫자의 단위, 평균의 분모, 시각의 시간대를 사용자가 이해할 수 있다.
- 새 측정 정책을 실기기 성능이 검증된 정책으로 과장하지 않는다.

우선순위는 기록 보존과 측정 신뢰성, 그다음 읽기 쉬운 상태 안내로 잡았다.
Android를 배포 우선 대상으로 유지하고, 공통 Flutter 코드와 iOS 어댑터의
확인된 오류도 함께 설계한다.

## 2. 배포 상태

`v0.9.1`은 2026-09-24 23:43:53 한국 시간에
[GitHub Release](https://github.com/devcsb/sanbo/releases/tag/v0.9.1)로 공개됐다.
AAB와 ABI별 APK 3개가 있으며, 현재 로컬 산출물의 SHA-256이 공개 산출물과
모두 일치한다. 로컬 `main`의 앞선 16개 커밋을 미배포 작업으로 판단하면 안 된다.
조사 시작 때 원격 기본 브랜치는 `b9fb762`에 남아 있어 공개 배포와 CI 기준 코드가
달랐다. 2026-10-14 이미 공개한 `1368d45`로 non-force fast-forward했고 해당
[main CI](https://github.com/devcsb/sanbo/actions/runs/38501773934)가 통과했다.
신규 0.9.2 후보는 별도 draft PR/릴리즈이며 main에 합치거나 공개하지 않았다.

Google Play 게시와 물리 Android/iPhone 검증 여부는 이번 조사에서 확인하지
못했다. GitHub 공개, 스토어 게시, 기기에 설치된 버전은 별개로 다룬다.

| M-11 | 원격 main, 릴리즈 문서, 실제 게시 상태 불일치 | GitHub release는 공개, 후보 문서는 외부 배포 보류 | P2 |
| M-12 | Health Connect 개인정보 안내 진입 불완전 | Android 14+ permission usage alias 및 정책 화면 누락 | 스토어 준비 P1 |
| M-13 | iOS에서 동작하지 않는 Android 전용 설정 버튼 노출 | 실제 iOS simulator AX tree에 Health Connect 설정 열기 | P2 |
| M-14 | 기록 화면에서 선택된 오늘 날짜가 가로 목록 밖에 있음 | 실제 simulator 화면, 선택 날짜를 드러내는 스크롤 없음 | P2 |
| M-15 | 이동/정지 시간 개별 반올림이 총시간을 초과함 | 실제 60초 기록에서 이동30초+정지31초=61초 | P2 |
| M-16 | 분 경계의 짧은 기록에서 분별 정수 시간 합계가 달라짐 | 실제 1초 기록이 두 분 행에서 각각1초로 저장 | P2, 시간 표현 계약 |
| M-17 | 과거 부분 제외의 세션 통계와 타임라인이 다름 | 20초 제외 후 세션35m/40초, 타임라인0m/60초 제외 | P2, 과거 백업 호환 |
| M-18 | 저장할 수 없는 좌표를 버리면서 경로 단절도 사라짐 | 위도91 좌표를 포함한 원본 필터 경로20m, 해당 행을 버린 checkpoint 복구40m | P2, 저장 경계 계약 |
| M-19 | 배경 지도 대신 API 키 안내 타일이 표시됨 | 실제 iOS 상세 화면과 기존 CARTO URL의 HTTP200 PNG에 `API KEY REQUIRED` 확인 | P1, 인증 구현과 정상 지도 검증 완료, 게시 전 |

M-19는 2026-10-14 실제 화면에서 추가로 확인했다. [CARTO 공식 안내](https://docs.carto.com/faqs/carto-basemaps#why-do-i-see-an-api-key-required-watermark)는 2026-09-25부터 키 없는 raster 요청에 지도를 제공하지 않는다고 설명한다. HTTP200과 PNG 형식만 확인해서는 정상 지도 표시를 증명할 수 없다.

M-04~06은 합성 입력에서 재현한 계산/정책 문제다. 물리 기기에서 발생 빈도나
새 알고리즘의 정확도를 측정한 결과는 아니다.

## 4. 요구와 수용 기준

### 4.1 1차 개선, 0.9.2 후보

| 요구 ID | 요구 | 수용 기준 |
|---|---|---|
| MR-01 | 모바일 외부 백업 저장을 지원한다 | Android 시스템 문서 저장, iOS 파일 내보내기에서 완료 후 실제 파일 재가져오기 가능. 취소/실패에는 저장 성공 안내 없음 |
| MR-02 | 복구와 완료가 같은 경로 경계를 쓴다 | 필터 제외 샘플, 60초 초과 GPS 공백, 세션 밖 좌표를 연결하지 않음. M-02 복구 및 완료 모두 10m |
| MR-03 | 현재 속도의 최신 여부를 구분한다 | 첫 유효 위치 전, 재개 직후 유효 위치 전, 마지막 유효 위치가 30초를 초과하면 `측정 대기` 또는 `측정 중단`. 측정 불가를 정지 0km/h로 표현하지 않음 |
| MR-04 | 모든 회상 화면은 산책 당시 시간대를 쓴다 | 서울 09시 샘플은 재생, 슬라이더 양 끝, 접근성 안내에서 09시. 기기 시간대 변경과 DST 중복 시간에서도 동일 순간 유지 |
| MR-05 | 모든 완료 export 평균 속도에 같은 공식을 쓴다 | 유효한 `totalDistanceM / movingTimeS`. 100m/100초는 JSON/NDJSON도 1m/s. 계산 불가 시 JSON null, 사용자 문구 `측정되지 않음` |
| MR-06 | 미연결과 읽기 오류를 구분하고 사용 가능한 설정만 노출한다 | 연결 전 `연결 전`, 거부 `권한 필요`, 읽기 실패 `불러오기 실패`, 유효 0걸음 `0걸음`. iOS에 Health Connect 설정 버튼 없음. GPS 거리에는 영향 없음 |
| MR-07 | 배포와 코드 기준을 대조할 수 있다 | 태그 커밋, 원격 브랜치, CI revision, 산출물 hash, 서명, 실제 게시 URL을 한 문서에서 확인 |

### 4.2 2차 개선, 측정 정책 고도화

| 요구 ID | 요구 | 수용 기준 |
|---|---|---|
| MR-08 | 작은 연속 이동을 보존하고 정지 흔들림을 억제한다 | 직선 30m/60초 합성 경로 오차 10% 이하, 5m 왕복 정지 fixture 누적 5m 이하. 둘을 같은 측정 규칙으로 처리하고 원본은 보존 |
| MR-09 | 지속성과 위치 품질을 확인한 고속 구간만 자동 제외한다 | 단일 15m 급증이 1분 전체 제외를 일으키지 않음. 연속 고속 이동은 감지. 사용자 확정 라벨과 제외 취소를 우선 |
| MR-10 | 병합 평균의 분모와 시간 합계를 일치시킨다 | 이동 시간 10초와 60초인 10m/90m 두 분의 병합 속도는 100/70m/s. 결측을 정지로 대체하지 않음. 이동/정지 정수 시간의 합이 총시간을 넘지 않으며, 짧은 분 경계 기록은 정확한 관측 시간과 표시용 정수 시간을 구분 |
| MR-11 | 측정 신뢰도를 사용자에게 설명한다 | 상세에 `평균 이동속도`, `GPS 예상 오차`, 측정 공백 시간을 구분. 정밀도 값은 실제 오차의 보장처럼 표현하지 않음 |
| MR-14 | 선택된 날짜와 접근성 동작을 분명히 한다 | 오늘 날짜/사용자가 선택한 날짜를 목록 진입과 주 이동 시 보이는 영역에 배치. 시작 CTA 중복 접근성 focus 여부를 검사하고 재현되면 하나로 통합 |
| MR-15 | 과거 백업의 부분 제외 범위를 정확히 표시한다 | 1분 중20초 제외를 60초 전체 제외로 표시하지 않음. 세션/지도/타임라인/export가 동일 포함 선분과 제외 시간을 설명. 기존 제외 ID와 사용자 수정, 취소 가능성 보존 |
| MR-16 | 저장 불가 좌표의 경로 단절을 복구에서도 보존한다 | 잘못된 위도/경도를 실제 좌표로 저장하지 않으면서 그 시각의 단절을 보존. M-18 원본/복구/완료가 같은20m. schema/백업 호환과 재계산 적용 범위를 별도 설계 |
| MR-17 | 외부 지도 서비스의 현재 인증 계약을 충족한다 | 실제 Android/iOS 상세 화면에 도로와 지명이 표시됨. 키 누락/인증 실패/네트워크 실패는 경로와 재생을 유지하며 상태를 설명. 키는 저장소/로그에 남기지 않고 공급자 안내와 출처 표시를 일치시킴 |

MR-17은 승인된 1차 MR-01~07에 포함되지 않은 긴급 추가 요구다. [지도 복구 설계](superpowers/specs/2026-10-14-basemap-service-restoration-design.md)와 구현 계획을2026-10-15 추가로 승인받아 구현했다. 2026-10-16 실제 키를 넣은 Android/iOS 정상 지도와 새 서명 후보를 검증했다. 두 OS의 키 누락/인증 실패, Android 실제 네트워크 단절도 확인했다. iOS 실제 네트워크 단절은 미검증이며 독립 PR 검토와 공개 확인을 마치기 전에는 게시하지 않는다.

2026-10-14 사용자는 MR-09의 방향으로 지속된 고속 이동과 GPS 품질을 함께
확인한 뒤 자동 제외하는 방식을 선택했다. 지속 시간, 속도와 품질 임계값,
과거 기록에 적용할 범위는 후속 설계에서 정한다. 이번 1차 수정에서 기존
10km/h 기준을 바꾸지 않는다.

## 5. 문구 제안

| 상황 | 제안 문구 | 목적 |
|---|---|---|
| 기록 중 속도 | `현재 속도` | 완료 평균과 구분 |
| 첫 유효 신호 전 | `GPS 신호를 기다리고 있어요` / `측정 대기` | 원시 callback만으로 기록 성공을 단정하지 않음 |
| 유효 위치 30초 초과 공백 | `GPS 신호를 기다리고 있어요. 마지막 위치는 30초 전에 받았어요.` / `측정 중단` | 이전 숫자의 최신성 설명 |
| 완료 요약 | `평균 이동속도`, `평균 이동 페이스` | 총 경과 시간이 분모라는 오해 방지 |
| GPS 오차 지표 | `GPS 예상 오차` | 기존 `중앙 정확도`보다 이해하기 쉬움 |
| Health 읽기 실패 | `불러오기 실패` / `건강 데이터를 다시 불러와 주세요` | 권한 연결 문제와 구분 |
| 자동 제외, 2차 정책 | `빠른 이동이 이어진 구간을 제외했어요. 산책한 구간이라면 제외를 취소할 수 있어요.` | 추정임과 복원 가능성 설명 |
| 개인정보 | `기록은 이 기기에 저장해요. 지도를 열 때 지도 타일 요청은 외부 서비스로 전달돼요.` | 로컬 기록과 지도 네트워크 요청의 차이 설명 |

## 6. 접근성, 성능, 데이터 유지

- 기존 세 탭과 지도/타임라인 구조, 큰 시작/종료 버튼을 유지한다.
- 현재 속도 숫자의 매초 갱신을 스크린리더에서 반복 읽지 않고 의미 있는 상태
  전환만 알린다. 320dp 폭, 1.8배 및 2배 글자, 밝고 어두운 테마를 확인한다.
- GPS 요청 간격, 정확도 상한, 5시간 종료, 위치 권한 정책은 1차에서 바꾸지 않는다.
- 1차에서 기존 SQLite 및 백업 형식을 유지하고 과거 기록을 자동 재작성하지 않는다.
- 2차 계산은 실측 오차와 느린 걷기 손실을 함께 평가한다. 정확도 반경만큼
  거리에서 매번 빼는 단순 보정이나 provider speed를 무조건 믿는 방식은 피한다.
- 5시간 합성 계산의 데스크톱 실행 결과를 휴대폰 배터리나 UI 프레임 성능으로
  해석하지 않는다.
