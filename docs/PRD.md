## 1. 문서 목적과 범위

본 PRD는 **산책을 분(minute) 단위 시간 윈도우로 기록**하고, 각 구간의 **이동 속도·장소**를 파악한 뒤, **당시 무엇을 했는지 가설(활동 추측)로 기록·조회**하는 위치기반 개인 앱의 제품 요구를 정의한다.

- **범위 안**: 제품 문제·목표, 사용자 시나리오, 기능/비기능 요구(ID 부여), 성공 지표, MVP 경계, 리스크·재검증 결론, **플랫폼·지도·심플 UX 제품 결정**.
- **범위 밖(Non-goals)**: 앱 코드 구현, 앱스토어 출시, Figma 시안, 실시간 코칭, 소셜, 웨어러블 심층 연동, 법률 자문 확정. (후속 단계 언급만 허용)
- **기술 상세**: [TRD](./TRD.md)에 위임. 플랫폼·지도 비교·결정은 [PLATFORM_AND_MAPS](./PLATFORM_AND_MAPS.md). 본 문서의 요구 ID는 TRD §12 추적 표와 1:1 대응한다.

## 2. 영감 / 레퍼런스 (Codex 모바일 GPS 추적)

워크스페이스 원본 이미지 2장을 제품 벤치마크로 사용한다.

| 파일 | 관찰 요약 |
|------|-----------|
| `산책, 달리기 추적 앱.jpg` | 사용자가 Codex(모바일, “s23제어프로젝트”)에 **「내가 달리기할건데 1시간동안 추적해봐」** 요청. 에이전트가 **1시간 GPS 추적 시작**, **기록 간격 약 2~3초**, **GPS 정확도 약 ±3.8m**, **자동 종료 1시간**, **NDJSON 로그** (`run-YYYYMMDD-HHmm.ndjson`), 종료 후 거리·실제 이동시간·평균 속도·평균 페이스 계산 약속. 추적 중 상태 메시지(정확도 ±3.8~4.5m 유지). |
| `산책, 달리기 추적 앱2.jpg` | 요청 시점 종료·분석 완료. 예정 1시간 vs **실제 기록 46:34**. **경로 맵**(출발 초록·도착 빨강·파란 동선, OpenStreetMap 계열). 요약 카드: 거리 **6.74 km**, 기록시간 **46:34**, 평균 페이스 **6:55/km**, 평균 속도 **8.68 km/h**. 상세: 추정 이동시간 **44:10**, 추정 이동 페이스 **6:33/km**, **정지·매우 느린 시간 약 2:24**, GPS 유효좌표 **932개**, 중앙 정확도 **±4.3m**, 1km 구간 페이스 시퀀스. |

### 2.1 레퍼런스가 잘 하는 것 (벤치마크)

1. **고주기 원시 GPS** (2~3초) → 거리·페이스·속도·정지 시간 산출  
2. **세션 단위 요약** + **경로 맵 시각화**  
3. **파일 로그(NDJSON)** 로 사후 분석 가능  
4. **정확도·유효 포인트 수** 투명 표시  
5. 대화형 “추적해줘” UX (에이전트 오케스트레이션)

### 2.2 산보(Sanbo)의 차별점 (OBJECTIVE 고유)

| 축 | 레퍼런스(Codex 러닝 추적) | 산보(목표 제품) |
|----|---------------------------|-----------------|
| 주 사용 목적 | 달리기 성과(거리·페이스) | **산책 동선·시간대별 행동 이해** |
| 시간 모델 | 세션 전체 + 1km 구간 | **분(minute) 단위 고정 시간 윈도우** 누적 기록 |
| 장소 | 맵 폴리라인 수준 | **장소/POI·장소 유형 파악** (역지오코딩·체류) |
| 의미화 | 수치 메트릭 중심 | **활동 추측(가설)+근거+신뢰도** 및 사용자 수정 기록 |
| 조회 단위 | 한 번의 러닝 세션 리포트 | **분 윈도우 타임라인** + 세션 요약 + “그때 뭐 했지?” 탐색 |
| 배포 형태 | 채팅+파일 일회성 | **전용 앱(세션 시작/종료, 로컬 우선 저장, 재조회)** |

> 한 줄 포지셔닝: *“러닝 워치가 아니라, 공개 지도 위에 산책의 ‘그때 그 1분’을 동선·속도·장소로 남기고 활동을 추측·수정하는 가벼운 개인 로그.”*

### 2.3.3 심플 UX — 러닝 앱에서 핵심만

| 가져옴 (Borrow) | 버림 (Reject) |
|-----------------|---------------|
| 큰 시작/종료 버튼 | 소셜·리더보드·챌린지 |
| 진행 중 숫자 3개(시간·거리·속도) | 랩/심박/고도/케이던스/칼로리 강조 |
| 종료 후 맵+요약 카드 | 훈련 계획·음성 코칭·장비 |
| 기록 목록 → 상세 | 상시 라이프로그·복잡한 연간 대시보드 |
| 기록 중 시스템 알림(FGS) | 마케팅 푸시·계정 온보딩 |

산보 고유는 **분 타임라인 + 활동 추정 칩 수정**만 추가하고, 화면은 **홈 / 기록 / 설정** 3탭을 넘지 않는다 (**D-UX-01~03**).

### 2.3.4 심플 게이트 (기능 추가 전 자문)

1. 시작 후 10초 내 기록 중 상태인가?  
2. 종료 후 **한 화면**에 맵+숫자가 끝나는가?  
3. “그때 뭐 했지?”가 타임라인 스크롤로 풀리는가?  
4. 서버 없이 삭제·데이터 위치가 설명되는가?  

하나라도 “아니오를 만들기 위해 기능을 줄여야” 하면 줄인다.

## 3. 문제 정의

### 3.1 문제

산책은 달리기에 비해 **목적·리듬이 혼합**된다(걷기, 카페 체류, 사진, 장보기, 벤치 휴식). 기존 피트니스 앱은 세션 총거리·칼로리 중심이라 **“어느 구간에서 무엇을 했는지”** 를 분 단위로 남기지 않는다. 사용자는 나중에 경로 맵만 보고는 **시간대별 맥락을 복원하기 어렵다.**

### 3.2 기회

스마트폰 GPS + (선택) 역지오코딩만으로도 **속도 대역·정지·장소 유형**을 조합하면, 확정은 아니나 **설명 가능한 활동 가설**을 세울 수 있다. 사용자가 사후 수정하면 **개인 로그 품질**이 올라간다.

### 3.3 목표 (Product Goals)

| ID | 목표 | 측정 방향 |
|----|------|-----------|
| G1 | 산책 세션을 **분 단위 윈도우**로 빠짐없이(허용 결측 정책 내) 기록한다 | 세션 내 윈도우 커버리지 ≥ 95% (권한·GPS 정상 시) |
| G2 | 각 윈도우의 **이동 속도·동선·장소 요약**을 제공한다 | 윈도우별 distance, speed, place 필드 존재율 |
| G3 | 윈도우/세그먼트 단위 **활동 추측 + 신뢰도 + 근거**를 남기고 사용자가 수정·확정할 수 있다 | 추측 생성률, 수정률, 확정률 |
| G4 | 세션 종료 후 **요약·타임라인·맵**으로 재조회한다 | 조회 완료 플로우 성공률 |
| G5 | 위치 데이터는 **사용자 통제·최소 수집·로컬 우선**으로 다룬다 | 원격 기본 전송 없음(MVP), 삭제 가능 |

### 3.4 비목표 (Out of Scope — MVP 및 v1)

- 실시간 러닝 코칭, 음성 페이스 안내, 랩·인터벌 UI  
- 소셜 피드, 친구 대결, 공개 공유(기본), 스트릭·배지 남발  
- 웨어러블/HealthKit/Health Connect **심층** 동기화 (후속으로 “읽기만” 가능 언급)  
- 칼로리·VO2·심박 기반 정밀 헬스 분석  
- 멀티유저 클라우드 동기·계정 시스템 (MVP)  
- **Google Maps / 카카오·네이버 맵 SDK** 를 기본 지도 엔진으로 사용  
- 상시(하루 종일) 위치 수집  
- 법률 자문 대체 문서, 개인정보보호법 **확정 해석** (체크리스트만)

## 4. 페르소나 · 시나리오

### 4.1 1차 페르소나: “기록형 산책자” (Primary)

- 혼자 또는 가볍게 동네·공원 산책. 성과 경쟁보다 **그날의 동선과 멈춤 이유**를 남기고 싶다.  
- 스마트폰 한 대, 백그라운드 위치 허용 가능. 배터리 과도 소모는 싫어함.  
- “카페에서 20분 있었다 / 강변을 빠르게 걸었다” 같은 **서술형 회상**을 선호.

### 4.2 2차: “일지 보완형” (Secondary)

- 일기·메모 앱 사용자. 산책 후 **시간 슬롯에 자동 초안**이 생기면 좋다.  
- 추측이 틀려도 고칠 수 있으면 수용.

### 4.3 핵심 사용자 시나리오

#### S1 — 기본 산책 기록 (Happy path) → 요구 FR-01~07, NFR-01

1. 앱에서 **산책 시작** → 위치 권한(항상/앱 사용 중+백그라운드) 확인.  
2. 걷는 동안 원시 위치 샘플 수집.  
3. 매 **1분 경계**에 윈도우 집계: 거리, 평균/최대 속도, 정지 비율, 대표 좌표, (가능 시) 장소.  
4. **산책 종료** → 세션 요약(총거리, 총시간, 이동/정지, 경로 맵).  
5. **분 단위 타임라인**에서 각 분의 속도·장소·활동 추측 확인.  
6. 틀린 추측을 **수정·확정** 후 저장.

#### S2 — 혼합 활동 (카페 들름)

- 20분 걷기 → 15분 실내 체류(GPS 노이즈/정지) → 다시 걷기.  
- 시스템은 체류 구간을 **정지/체류**로 묶고, 인근 POI가 카페면 추측 `cafe_stay` (낮은~중간 신뢰도).  
- 사용자 확정 또는 “친구 만남”으로 수정.

#### S3 — GPS 불량 (도심 협곡·실내)

- 정확도 악화·점프. 윈도우는 **저품질 플래그** + 거리 과대 추정 억제.  
- 활동 추측은 `unknown` 또는 낮은 신뢰도로 억제 (과신 금지).

#### S4 — 사후 회상 (“3시쯤 뭐 했지?”)

- 세션 목록 → 해당 세션 → 타임라인 스크롤 또는 시간 검색 → 그 분 윈도우의 맵 스니펫·장소·추측·메모.

#### S5 — 권한 거부 / 백그라운드 제한

- 명확한 안내, 포그라운드-only 모드(가능 범위 축소) 또는 기록 불가 상태. 조용한 실패 금지.

## 5. 핵심 개념 정의

| 용어 | 정의 |
|------|------|
| **세션 (Session)** | 사용자가 시작~종료한 한 번의 산책 기록 단위. |
| **원시 샘플 (LocationSample)** | GPS 등에서 얻은 단일 위치 점 (시각, lat/lon, accuracy, speed 등). |
| **분 윈도우 (MinuteWindow)** | 벽시계 기준 1분 구간 `[t, t+60s)` 에 속한 샘플을 집계한 레코드. 산보의 **1급 기록 단위**. |
| **세그먼트 (Segment)** | 인접 윈도우를 동일 활동/체류로 병합한 구간(선택, MVP+). |
| **장소 요약 (PlaceSummary)** | 역지오코딩·체류 클러스터 결과 (이름, 카테고리, 체류 여부). |
| **활동 추측 (ActivityHypothesis)** | 규칙/휴리스틱이 산출한 **가설 라벨** + confidence + evidence. **사실이 아님**. |
| **사용자 라벨** | 사용자가 수정·확정한 활동. 추측보다 우선. |

### 5.1 분 윈도우 정책 (제품 규칙)

- **정렬**: 로컬 타임존 벽시계 분 경계 (예: 14:03:00–14:03:59.999).  
- **부분 분**: 세션 시작/종료 분의 윈도우는 `partial=true`, duration_s < 60 가능.  
- **빈 윈도우**: 샘플 0개인 분은 `missing` 또는 `gap`으로 남기되 타임라인 구멍은 표시.  
- **이유**: 사용자 회상은 “몇 시 몇 분” 기준이 자연스럽고, 1km 구간 분할(레퍼런스)보다 **시간 축 일기**에 맞음.

### FR: 고속 이동 종료 확인과 기록 구간 제외

- 최근 120초 안에서 신뢰 가능한 28.8km/h 이상 이동이 누적 60초가 되면 자동 종료하지 않고 종료 여부를 확인한다.
- 사용자는 `기록 종료` 또는 `계속 기록`을 선택하며, 14.4km/h 이하 이동이 연속 30초 이어지기 전에는 같은 이동으로 다시 알리지 않는다.
- 완료 기록의 연속 구간에는 `산책에서 제외`를, 제외된 구간에는 `제외 취소`를 제공한다.
- 편집 성공 뒤 지도, 세션 통계, 기록 화면 합계와 일별 합계를 함께 새로 읽는다.

## 13. 다방면 검토 · 재검증 (제품 관점 요약)

상세 챌린지·결론은 **§14** 및 TRD §11과 함께 유지한다. 제품 문서에 고정하는 **재검증 결론**:

1. **사용자/제품**: 러닝 클론이 되면 실패. 성공 기준은 “분 타임라인으로 회상 가능한가”.  
2. **데이터·정확도**: 분 윈도우 거리의 합 ≠ 세션 필터 거리일 수 있음 → 세션 롤업은 **재계산 경로**를 표준으로(TRD).  
3. **모바일 제약**: 백그라운드 킬·정확도 저하를 1급 시나리오(S5)로 취급.  
4. **프라이버시/법무**: MVP 무서버로 표면적 리스크 축소; 지오코딩 네트워크는 별도 고지.  
5. **추측 한계**: 라벨 집합 축소·unknown 권장; `vehicle` 등은 높은 임계.  
6. **대안**: (a) 1km 구간만 (b) 세션 요약만 (c) 수동 태그만 — 모두 회상 시나리오 S4를 약화하므로 **분 윈도우+가설** 유지, 대신 정확도 약속 축소.

## 14. 다방면 검토·재검증 기록 (심층)

각 축: **가정 → 위험 → 완화 또는 의도적 범위 축소**. (수용 기준 AC-4: ≥4축)

### 축 A — 사용자 / 제품 가치

| 항목 | 내용 |
|------|------|
| 가정 | 사용자는 “총 걸음”보다 **시간대별 맥락**에 가치를 둔다. |
| 위험 | 맵+숫자만 보여 주고 활동 추측이 빈약하면 일반 트래커와 무차별. 반대로 추측이 시끄러우면 피로. |
| 완화 | 타임라인을 기본 탭; 추측은 접을 수 있게; 수정 1탭. 카피에서 산책·회상 강조. |
| 범위 축소 | 소셜 비교·배지·스트릭은 MVP 제외(동기보다 로그 정직성). |

### 축 B — 데이터 · 위치 정확도

| 항목 | 내용 |
|------|------|
| 가정 | ±3–5m**급 야외 GPS면 보행 속도 대역 분류에 충분; 실내는 불가. |
| 위험 | 멀티패스 점프로 분당 거리 급증 → “뛰기” 오탐. 윈도우 합산 거리 이중 계산. |
| 완화 | accuracy·max jump 필터; 세션 거리는 필터된 샘플 경로로 **단일 롤업**; 저품질 윈도우 `quality=low`. |
| 범위 축소 | 고도·실내 층수·지하철 노선 스냅은 v1 이후. |

### 축 C — 모바일 제약 (백그라운드 · 배터리 · 권한)

| 항목 | 내용 |
|------|------|
| 가정 | iOS/Android 모두 백그라운드 위치는 **OS 정책·사용자 설정**에 종속. |
| 위험 | 앱 종료·배터리 최적화로 샘플 공백; “몰래” 고주기 수집은 스토어·신뢰 리스크. |
| 완화 | 포그라운드 서비스/블루바 등 플랫폼 정석; 배터리 모드 3단(TRD); gap 타임라인 표시; 권한 교육 화면. |
| 범위 축소 | 완전 화면 꺼짐 + 절전 극한에서의 100% 커버리지는 **약속하지 않음**(NFR-01에 조건 명시). |

### 축 D — 프라이버시 / 법무 리스크

| 항목 | 내용 |
|------|------|
| 가정 | 위치 경로는 민감정보; 한국 개인정보보호법·플랫폼 가이드라인 고려 필요(자문 아님). |
| 위험 | 서버 전송 시 목적·보관 이슈; 스크린샷·export 유출; 지오코딩 벤더 로그. |
| 완화 | MVP 로컬 전용; 삭제; export 사용자 명시 동작; 지오코딩 시 반올림/캐시·벤더 DPA 검토 체크리스트(TRD). |
| 범위 축소 | 클라우드 계정·공유 링크는 later + 별도 PRD 개정. |

### 축 E — 활동 추측의 한계 · 오탐

| 항목 | 내용 |
|------|------|
| 가정 | 속도+정지+POI+시간대만으로는 **의도(대화, 생각)** 를 알 수 없다. |
| 위험 | “카페” POI 근처 횡단보도 대기를 cafe로 표기; 버스 정체를 walk로 표기. |
| 완화 | evidence 노출; confidence 임계; `place_stay` vs `cafe_or_shop` 분리; 사용자 라벨 우선; 오탐 많은 라벨 제거·병합 가능. |
| 범위 축소 | 감정·생산성·만남 상대 추론 **금지**. LLM 자유 서술 자동 생성은 later(환각 위험). |

### 축 F — 대안 비교

| 대안 | 장점 | 단점 | 결정 |
|------|------|------|------|
| A. 세션 요약만 (Strava-like lite) | 단순, 배터리↓ | S4 회상 실패 | 기각(핵심 차별 상실) |
| B. 1km 구간 분할 (레퍼런스) | 러닝에 익숙 | 산책 체류·분 회상 부적합 | 보조 지표로만 later |
| C. 수동 태그만 | 정확 | 기록 마찰↑, 미기록 | 수정 UI로만 채택 |
| D. **분 윈도우 + 규칙 추측 + 수정** | 회상·자동화 균형 | 구현·오탐 관리 필요 | **채택 (본 PRD)** |
| E. 상시 라이프로그 (하루 종일) | 완전 기록 | 배터리·프라이버시 심각 | **비목표** (명시 세션만) |

### 재검증으로 문서에 반영한 변경 (v1.0 → v1.1)

- 활동은 “분류 결과” → **가설+confidence+evidence** 로 용어 통일.  
- 세션 거리 = 윈도우 거리 합이라는 암시 제거 → **롤업 재계산**.  
- 백그라운드 100% 커버리지 약속 삭제 → 조건부 NFR-01.  
- 상시 추적은 대안 기각으로 명시.  
- `vehicle` 등 고위험 라벨은 높은 임계(TRD 규칙 표).
