# CARTO 운영 확인과 광고 도입 조건

2026-10-18 사용자 로그인 뒤 소유 계정의 dashboard를 읽었다. 키, 이메일, 계정 ID,
인증 URL과 결제 링크의 개인 매개변수는 이 문서에 기록하지 않는다. 설정을 저장하거나
키를 생성/폐기/제한하지 않았다.

## 실제 확인

| 항목 | 확인한 내용 |
|---|---|
| 요금제와 용도 | `Free plan`, `Non-commercial` 표시 |
| 한도와 사용량 | 월 5M 중 204 requests. 화면은 UTC 월초부터 **2026-10-16까지** 집계했다고 표시한다. 실시간 사용량이나 현재 누적 전체로 단정하지 않는다. |
| 키 상태 | 키 1개, `Active`, `Unrestricted` |
| 기존 키 제한 | 웹 Referer, 모바일 앱, 원본 IP 제한을 제공한다. 편집 화면을 읽고 Cancel로 닫았다. |
| Android 제한 형식 | 공개 신청 양식에 package name + app signing SHA-1이라고 표시한다. 헤더는 `X-Android-Package`, `X-Android-Cert`다. |
| iOS 제한 형식 | iOS bundle ID와 `X-Ios-Bundle-Identifier` 헤더를 안내한다. |
| 상업용 전환 | dashboard에 `Switch to commercial`을 제공한다. 이 버튼은 실행하지 않았다. 유료 Commercial 구독 링크와 별개의 UI다. |
| 추가 청구/자동 구매 | 현재 화면은 무료 요금제를 표시한다. 등록 결제 수단의 유무, 한도 초과 시 차단/초과 청구를 확정하는 계정 문구는 확인하지 못했다. |
| 사용량 상한/알림 | 읽은 계정/키 편집 화면에서 별도 상한 또는 알림 설정을 확인하지 못했다. 공급자가 기능을 제공하지 않는다고 단정하지 않는다. |

직접 타일 요청 재현에서는 무키/invalid 키는 안내 PNG, 앱에서 회수한 현재 키는
무헤더 외부 클라이언트에도 정상 PNG를 반환했다. 기존 배포 키는 여전히 재사용할 수 있다.

## 광고 도입 전

[공식 FAQ](https://docs.carto.com/faqs/carto-basemaps)와
[Basemap 약관](https://carto.com/legal/basemap-terms/)을 2026-10-18에 확인했다.
광고 수익은 상업용 사용에 포함한다. 상업용 무료 한도는 월 100만 타일이며 계정 내
모든 키와 raster/vector 사용을 합산한다. 현재 비상업용 500만 한도를 광고 배포에도
적용된다고 가정해서는 안 된다. 광고를 넣기 전에 용도 분류를 변경하고 적용 결과를 확인한다.

현재 앱에는 광고 SDK가 없다. 향후 광고 작업에서는 SDK 수집 항목, 위치 접근,
개인정보처리방침, 필요한 동의와 스토어 신고를 별도로 검증한다.
[Google Android 건강 권한 정책](https://support.google.com/googleplay/android-developer/answer/12991134?hl=en)에
따라 건강/걸음 데이터를 광고 제공이나 타기팅 입력으로 전달하지 않는다.

다음 계정 질문은 아직 미해결이다. 확인 전 비용이 항상 0원이라는 보장은 하지 않는다.

- 무료 한도 초과 시 hard block, rate limit, 유료 계약 요구 중 어떤 처리를 하는지
- 유료 계약/결제 수단 없이 자동 초과 청구나 구독 생성이 가능한지
- 계정 전체 요청 상한과 사용량 알림을 설정할 수 있는지
- 계정/키별 집계 지연과 제한 적용/타일 캐시 지연이 얼마인지

지원 문의가 필요하면 `support-basemaps@carto.com`에 위 사항과 계정 식별 정보를
본인이 전달해 확인할 수 있다. 이번 작업에서 문의 메일은 보내지 않았다.

## 제한과 키 전환

모바일 제한을 설정하려면 공급자가 요구하는 SHA-1/패키지 값과 일치하는 요청 헤더를
새 앱에서 보내야 한다. 기존 v0.9.3은 해당 헤더를 보내지 않으므로 기존 키에 제한을
즉시 켜거나 폐기하면 이미 설치한 앱의 지도가 끊긴다. 현재 키/설정은 유지한다.

별도 키로 후보를 만들고 정상 요청, 무헤더, 잘못된 헤더, 공개 식별자를 복제한 헤더를
비교한 뒤 전환 일정을 정해야 한다. 이 제한 키의 대조 검사는 아직 실행하지 않았다.
헤더 자체는 공개 식별자이므로 그것만으로 앱 진위를 증명한다고 설명하지 않는다.
키 교체나 난독화만으로 추출을 막을 수도 없다.

사용량은 사용자 수만으로 예측할 수 없다. 지도 열기/확대/축소와 메모리 캐시를 포함해
대표적인 사용 흐름에서 측정해야 한다. 외부 재사용으로 발생한 요청도 남은 위험이다.
강한 남용 제한이 필요하면 앱 증명을 검증하고 전체 사용량 상한을 두는 서버 방식을
별도로 설계한다. 공개 프록시 하나로 타일을 전달하는 것만으로 해결됐다고 보지 않는다.

## 2026-11-07 후속 검토

공식 [Basemaps FAQ](https://docs.carto.com/faqs/carto-basemaps)를 다시 읽었다. 문서가
안내하는 모바일 제한은 위 공개 패키지/인증서 헤더다. 비상업용 월 500만, 상업용
월 100만 요청의 무료 범위와 초과 상업용 유료 계약 필요도 여전히 설명한다.
이 확인은 계정 dashboard의 현재 설정이나 결제 수단, 초과 시 자동 차단/청구 처리를
새로 확인한 결과가 아니다. 해당 계정 질문은 위 미해결 목록에 남는다.

앱 제한의 식별자는 비밀이 아니다. 헤더만으로 앱 진위를 입증할 수 없다는 판단은
공개 식별자를 클라이언트가 전송하는 구조에서 한 추론이다. 새 제한 키에서 복제
헤더를 대조한 공격 시험을 이번에 수행한 것으로 표현하지 않는다. 기존 키와 광고
용도, 계정 제한은 바꾸지 않았다. 기존 앱의 지도를 끊지 않기 위해 전환은 별도
키의 새 후보 검증, 업데이트와 구버전 만료 안내 순서로 진행해야 한다.

강한 방어가 필요하면 신뢰 경계는 서버로 옮긴다. 후보 설계는 앱 증명 검증과 재사용
방지, 짧은 유효 기간의 인증, 사용자/설치/전체 사용량 제한, 허용하는 지도 경로와
범위만 전달하는 서비스, 429와 지도 실패 복구를 함께 다룬다. 공개된 무인증 프록시는
새로운 남용 창구가 될 수 있다. 외부 키/URL/오류 원문은 로그에 남기지 않고 서버가
관측하는 표시 위치와 IP의 보관/고지도 설계해야 한다.

이 방식은 서버 운영과 앱 증명 공급자 선택, 비용 상한과 개인정보 경계 결정이
필요하다. 새 서버, 요금제, 키 폐기나 제한 변경을 로컬 표시 개선과 몰래 함께
배포하지 않는다. 현재 앱의 키 추출 가능성을 해결했다는 안내도 추가하지 않는다.
