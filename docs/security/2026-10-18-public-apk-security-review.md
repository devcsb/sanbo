# 산보 v0.9.3 공개 APK 보안 검토

검토일: 2026-10-18. 상태: 조사 완료, 아래 개선안은 구현 전.

## 판정

CARTO 연동은 현재 정상이다. 공개 APK에서 회수한 키로 실제 지도 PNG를 받았고, 무키와 임의 키로는 인증 안내 PNG를 받았다. CARTO는 배경 지도만 제공한다. GPS 수집, 거리와 속도 계산, 기록 저장, 자동 고속 제외는 앱에서 처리한다.

공개 APK 안의 CARTO 키는 추출과 외부 재사용이 가능하다. 비공개 빌드 설정은 Git 유출을 막지만 배포 바이너리에 들어간 값을 비밀로 만들지는 않는다. 다른 사용자가 이 키로 지도 요청을 보내 사용량을 소모할 수 있다. 현재 검사는 타일 읽기만 확인했으며, CARTO 계정 관리나 결제 접근 권한을 얻었다는 증거는 없다.

현재 앱은 광고 SDK를 포함하지 않는다. 사용자는 광고 도입을 고려 중이라고 밝혔다. 광고 수익이 발생하면 CARTO 상업적 이용에 해당하므로 현재 비상업용 등록을 변경해야 한다. 유료 계약, 결제 수단, 계정별 실제 사용량과 차단 설정은 이번에 확인하지 않았다.

## 대상과 방법

- [공개 v0.9.3 릴리스](https://github.com/devcsb/sanbo/releases/tag/v0.9.3)에서 arm64 APK를 새로 내려받았다.
- 크기 21,840,706 bytes, SHA-256 `12acd6d72c2cac7bfb4c2212aafa94cb387e5fc082fc2fc17be9ecf79d1559f6`.
- 서명 대상 소스 `b00f5cd9ecc9366b611f96994bfec3c123f2bd9e`. 검토 시 main `3e307e3f02513adc50ddbf6ddeae83cf87eca1f0`. 후자는 릴리스 뒤 문서 변경이다. 원격 main도 같은 커밋임을 확인했다.
- Android API 34의 소유한 QA 에뮬레이터에서 설치된 APK를 다시 가져와 공개 APK와 같은 해시임을 확인했다. 앱 데이터 초기화, 삭제, 권한 강제 부여는 하지 않았다.
- 먼저 배포 바이너리를 분석한 뒤 소스와 대조했다. 토큰 형태와 엔트로피로 후보를 추출한 후에만 로컬 빌드 설정과 일치 여부를 비교했다. 키 값을 검색어로 사용해 찾은 결과가 아니다.
- 기존 설치된 REA 6.5.0을 Node 24.14.1로 실행했다. 새 패키지 설치나 전역 MCP 설정 변경은 없었다. 실행 환경에는 일반 경로와 로케일 등 필요한 값만 전달했다.
- REA `inspect-artifact`, `identify-flutter-build`, `inspect-adb-package`, `start-adb-activity`를 실제 실행했다. 바이트 분석, APK manifest와 DEX 분석, HTTP 대조, 서명 검증은 Python stdlib와 Android SDK 도구로 보완했다.
- 이 문서의 검토는 Codex 실행자가 직접 수행했다. 사용자 AGENTS의 재위임 금지에 따라 별도 모델의 독립 컨텍스트 검토는 실행하지 않았다. REA는 분석 도구이며 독립 보안 검토자나 자동 침투 에이전트가 아니다.

실제 키, 키가 붙은 URL, 원본 GPS, 비밀번호는 이 문서나 Git에 기록하지 않았다. 원시 증거는 저장소 밖 소유자 전용 디렉터리 `~/.local/share/sanbo-security-audit/2026-10-18/`에 보관했다. 디렉터리 권한은 0700, 분석 출력은 0600으로 제한했다. 토큰 후보를 평문으로 나열한 임시 사본은 검사 뒤 제거했다. APK 자체에는 공개 클라이언트 키가 들어 있다.

P1은 먼저 다룰 운영 위험을 뜻한다. 사용자 계정 탈취나 임의 코드 실행이 입증됐다는 의미가 아니다.

### SEC-01 외부 재사용 재현

자신의 키로 동일한 공개 지도 타일에 세 번의 읽기 요청만 보냈다. 임의의 일반 User-Agent를 사용했고 Android/iOS 식별 헤더와 웹 Origin/Referer는 보내지 않았다. 부하 테스트, 대량 타일 수집, 한도 소진, 계정 변경 요청은 하지 않았다.

| 요청 | HTTP | PNG bytes | ETag | 이미지 |
|---|---:|---:|---|---|
| 키 없음 | 200 | 2,049 | `"wm-6dc6c2207e69-light"` | API KEY REQUIRED 안내 |
| 합성 invalid 키 | 200 | 2,049 | 같은 값 | 같은 안내 |
| 공개 APK에서 회수한 키 | 200 | 6,249 | `"martin-20261001-02"` | 도로와 지명이 있는 정상 지도 |

앞의 두 이미지는 SHA-256이 같았다. 마지막 이미지는 달랐고 실제 픽셀도 확인했다. HTTP 200이나 PNG 여부만으로 인증 성공을 판정하면 안 된다.

### SEC-02 원인과 재현

`lib/shared/widgets/carto_basemap.dart`에서 `"wm-da89c20e77c1-light"`와의 완전 일치만 검사한다. 현재 응답은 그 값과 다르므로 `onAuthenticationNotice`를 호출하지 않는다. `CartoTileProvider`는 이 콜백을 통해 안내 타일을 캐시에서 빼고 화면에 실패 상태를 알린다.

저장소 밖 진단 테스트에 실제 무키 응답의 PNG와 ETag를 넣었다. 기대한 콜백 횟수는 1, 실제는 0이었다. 같은 진단 실행에서 백업 SQL 문자열 보존과 잘못된 좌표의 트랜잭션 취소 검사는 통과했다. 결과는 **2 통과, 1 실패**다. 현재 제품 코드는 아직 수정하지 않았다.

공개 APK의 서명은 v2 검증에 통과했다. 인증서 SHA-256은 `ceb40402d706589acee5da5df5a010c3dd5c2e9329cd3218961dfce56a6d38ac`다. 인증서 공개 정보와 공개키를 읽는 것은 서명 개인키 추출과 다르다. 인증서 subject에는 `Android Debug`가 있지만, 로컬 설정은 기본 debug.keystore 위치/파일과 다르고 기본 Android 비밀번호 값과도 달랐다. subject 문자열만으로 키가 탈취됐거나 모두가 아는 개인키라고 판정하지 않았다. 기존 업데이트 호환성을 깨는 서명 키 변경은 권고하지 않는다.

### 외부로 노출된 Health Connect 구성요소

merged manifest에는 라이브러리의 `HealthDataSdkService`가 exported=true로 추가된다. 실제 APK DEX를 읽어 Binder 진입 경로를 확인했다. 해당 구현은 호출 UID에 속한 패키지인지 검사하고 `com.google.android.apps.healthdata`만 허용한 뒤 permission-token/foreground 콜백 작업을 실행한다. 단순히 exported=true라는 이유로 건강 데이터 공개 취약점으로 판정하지 않았다. 별도 악성 APK에서 Binder를 호출하는 동적 검사는 실행하지 않았다.

`ProfileInstallReceiver`도 exported=true지만 `android.permission.DUMP`가 필요하다. 일반 앱에서 보호를 우회했다는 증거는 없다. ADB shell은 일반 앱보다 권한이 높으므로 shell의 성공만으로 우회 취약점이라고 주장해서는 안 된다.

## 여러 사용자가 사용할 때의 운영 영향

현재 앱에는 회원 서버와 원본 GPS 업로드 API가 없다. 다른 사용자가 APK를 설치한다고 개발자 폰의 산책 DB가 그 사용자에게 복제되지는 않는다. 기록, 거리/속도, 타임라인, 장소와 메모, 경로 재생, 백업/복원, 고속 이동 자동 제외와 취소를 각 기기에서 사용할 수 있다. 실제 기기의 GPS 정확도와 장시간 배터리 품질은 이번 검사의 대상이 아니다.

지도는 외부 서비스다. 사용자가 지도 화면을 열면 CARTO가 타일 영역과 IP 등 요청 정보를 받는다. 주소 제안은 사용자 요청으로 OS 지오코더에 좌표를 전달할 수 있다. 수동 `.sanbo` 백업은 암호화하지 않은 JSON이며 정밀 경로와 메모를 포함한다. 현재 내보내기 경고와 시스템 파일 선택기를 확인했다. 사용자가 클라우드나 타인에게 파일을 보내면 별도 노출 경로가 된다.

### 광고, 무료 한도와 비용

2026-10-18에 확인한 [CARTO 공식 FAQ](https://docs.carto.com/faqs/carto-basemaps)는 비상업용 월 500만, 상업용 월 100만 타일 요청까지 무료라고 안내한다. 요청은 계정의 모든 키와 raster/vector를 합산한다. 그 이상은 별도 유료 요금제 대상이다. 광고 수익도 상업적 사용에 포함한다는 근거는 [Basemap 약관 1.7, 3, 8절](https://carto.com/legal/basemap-terms/)이다. 운영자가 키 사용을 모니터링하고 제한할 책임도 명시한다.

키를 안다고 그 자체로 유료 구독을 구매하거나 개발자 카드로 결제할 수 있다는 증거는 없다. 다만 재사용으로 사용량이 증가하거나 제한/정지가 발생할 수 있고, 유료 계약이 있다면 실제 청구 조건은 그 계약을 확인해야 한다. 무료 한도 초과 시 계정에서 정확히 어떻게 차단하는지, 자동 추가 청구가 있는지 등은 계정 설정/공급자 확인 없이 보장하지 않는다.

무료 사용이 충분한지는 가입자 수만으로 알 수 없다. 월 요청량은 활성 사용자 수, 지도 여는 횟수, 화면당 타일 수, 확대/축소와 캐시에 따라 달라진다. 예를 들어 1,000명 × 하루 1회 × 20타일 × 30일이면 60만 요청이지만, 이는 산보 실측치가 아닌 계산 예시다. 외부 재사용은 이 추정에 포함되지 않는다.

현재처럼 기기가 직접 지도를 요청하면 별도 산보 서버는 필요 없다. 패키지/인증서 헤더 제한은 일반적인 무헤더 재사용을 줄일 수 있으나 공개 값을 복제하는 공격까지 인증하지 못한다. 더 강한 통제가 필요하면 검증된 앱 증명, 서버 단위 한도와 전체 사용량 상한이 필요하다. 키를 숨기는 프록시만 추가하면 그 프록시가 새 공개 요청 창구가 될 수 있다.

광고 도입 시 건강/걸음 데이터를 광고 대상으로 사용하면 안 된다. [Google의 Android 건강 권한 정책](https://support.google.com/googleplay/android-developer/answer/12991134?hl=en)은 건강/피트니스 데이터를 광고 제공에 이용하거나 광고 사업자에게 전달하는 사용을 금지한다. 광고 SDK의 실제 수집 항목, 위치 접근, 공개 개인정보처리방침과 스토어 신고는 광고를 설계할 때 별도로 확인해야 한다. 이번에 광고 SDK나 광고 동의 화면을 추가하지 않았다.

## 한계와 후속 검증

- REA `identify-flutter-build`는 Flutter와 라이브러리 해시를 확인했지만 coverage=partial이다. snapshot hash는 `0451907c2eaa8467e848c0067bfe8ed4`였다.
- `inspect-dart-aot`는 인식하는 dynamic snapshot symbol이 없어 unsupported_target을 반환했다. `inspect-binary-layout`도 설치된 버전의 공급자가 Linux x64만 지원해 실행되지 않았다. 이를 Dart 전체 역컴파일이나 네이티브 메모리 안전성 검증 성공으로 표현하지 않는다.
- JADX 엔진은 현재 환경에 없어서 REA의 Java 역컴파일 기능을 사용하지 않았다. 관련 exported service는 Android SDK의 실제 DEX 코드 조회로 보완했다.
- iOS 바이너리 보안, 물리 기기, 루트/탈옥, 모든 이전 ABI/버전, 완전한 네트워크 MITM, 인증된 CARTO dashboard의 실제 계약/제한, 의존성 전체 취약점 DB 조사는 미검증이다.
- 기준 키의 실제 사용자에 대한 악용 이력은 확인하지 않았다. 이번 외부 재사용 성공을 과거 탈취가 있었다는 증거로 해석하지 않는다.
- 코드 변경, 키 폐기/회전, 공급자 설정 변경, PR/추가 릴리스는 아직 실행하지 않았다.
