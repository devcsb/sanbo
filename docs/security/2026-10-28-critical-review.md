# 요약 구현 이후 비판적 검토

2026-10-28 검토. 기준 커밋은 `6f2e0ae`다. 이번 검토는 현재 작업 브랜치의 소스와
격리된 합성 입력을 대상으로 했다. 공개 APK 전체의 신규 침투 시험이나 외부 독립
보안 감사로 표현하지 않는다. 사용자 지침에 따라 재위임 없이 직접 검토했다.

## 판단

요약 UI 구현만으로 기존 보안/측정 문제가 해결되지는 않았다. 백업 입력의 가용성
문제를 다음 구현에서 먼저 처리할 것을 권한다. 원본 GPS와 사용자 라벨을 보존하고,
외부 입력을 거부하거나 오류를 표시하되 과거 기록을 몰래 수정하지 않는 방향이다.

기존 승인 설계와 어긋난 패널 취소 동작은 이번에 수정했다. 백업/반출 정책은
[기존 보안 설계](../superpowers/specs/2026-10-25-import-and-privacy-boundaries-design.md)의
승인 전이므로 이 검토에서 새 상한이나 공유 정책을 제품에 도입하지 않았다.

## 우선순위와 재현 결과

P1/P2는 작업 우선순위이며 CVSS 등급이 아니다. 이번 문제 대부분은 이전 검토의
미해결 항목을 현재 소스에서 재확인한 것이다.

| 우선순위 | 발견 사항 | 이번 증거/영향 |
|---|---|---|
| P1 | 백업의 정수 합산 overflow | 625바이트 백업의 세션 2개를 가져온 뒤 `completedStats()`가 SQLite `integer overflow`로 실패했다. 개별 목록은 조회되지만 `completedHistoryProvider`가 집계와 목록을 함께 반환해 정상 목록까지 오류 화면으로 갈 수 있다. |
| P1 | 입력 길이와 실제 계산량의 불일치 | 409바이트로 천 년 범위를 가져왔고 525,948,480분을 나타냈다. 이 전체 범위의 재계산은 실행하지 않았다. 7일 예제만 계산했으며 window 0개가 10,080개가 됐다. |
| P1 | Android 크기 검사가 native 할당 뒤에 있다 | 잠금 버전 `file_selector_android 0.5.2+9` 소스에서 provider SIZE로 `new byte[size]` 후 `readFully`, 이어 별도 cache 복사를 실행한다. Dart의 50MiB 검사는 그 뒤다. 실제 OOM 시험은 하지 않았다. |
| P2 | 정밀 경로/메모의 무확인 클립보드 반출 | 실제 상세 위젯의 데이터 복사 1회로 합성 GPS와 메모가 `Clipboard.setData`에 전달됐다. 확인창은 없었다. 외부 앱의 탈취를 시험한 것은 아니다. |
| P2 | GPS 흔들림을 이동 성과로 누적할 수 있다 | 정지를 가정한 정확도 30m, provider speed 0, 10초 간격 왕복 합성 입력에서 3분에 거리 360.3m, 이동 시간 180초가 됐다. 실제 기기 측정은 아니다. |
| P2 | 실패 기록의 보관과 안내가 다르다 | discarded 좌표 1개는 내부에 남지만 기록 목록/전체 백업에는 나타나지 않았다. 현재 원본 보존 결정과 연결되므로 자동 삭제하지 않았다. |
| P2, 수정 | 취소된 페이지 드래그가 새 패널을 확정한다 | PageView를 절반 이상 이동하고 PointerCancel을 보내면 원래 경로 대신 주간 패널이 남았다. 양방향 취소와 다중 터치 종료를 원래 패널로 복구하도록 수정했다. |
| P2, 개발 도구 | 중단한 검사 실행을 PASS로 오인할 여지가 있다 | 이전 로컬 `build/walk-summary-quality-final.log`에는 전체 테스트 완료/새 APK 생성 문구 없이 `[quality] PASS`가 있다. 중단 시 하위 Flutter 명령이 성공으로 반환되는 경우까지 shell exit code만으로 구분하지 못한다. 최종 검증에서는 완료 문구와 산출물을 따로 확인한다. |

백업의 개별 유한 실수 거리 `1e308` 두 개도 합계 `Infinity`를 만들었다. 정수만
검사하거나 SQL 바인딩을 사용하는 것만으로 수치 집계의 안정성을 보장할 수 없다.
공격자가 원격으로 임의 코드를 실행하거나 계정을 탈취하는 경로는 이번에 입증하지
않았다. 백업 문제는 사용자가 외부 파일을 선택하고 가져오는 조건이 필요하다.

## 새 요약 UI에서 수정한 부분

기존 [승인 설계](../superpowers/specs/2026-10-26-walk-summary-interaction-design.md)는
취소/다중 터치가 페이지를 임의 확정하지 않도록 했다. 기본 PageView의 취소 후
정착 동작만으로는 이 계약을 충족하지 못했다.

`SessionSummaryPanels`에서 포인터 입력 시작 시 선택을 기억하고, 시스템 취소나
다중 터치가 끝난 뒤 그 선택으로 복구한다. 제스처 인식기를 새로 등록하거나 OS
뒤로가기와 경쟁하지 않으며 Flutter의 기본 한 손가락 밀기는 유지한다. 변경은
표시 페이지에 한정되고 기록/DB/원본 좌표를 수정하지 않는다.

먼저 회귀 테스트 2개가 실제로 `expected 0, actual 1`로 실패했다. 첫 테스트
harness는 TextField가 드래그를 받아 잘못된 위치를 검사했으므로, 제스처 영역을
분리한 재현으로 수정한 뒤 RED를 확인했다. 구현 후에는 반대 방향 복귀, 다중
터치의 정상 종료, 취소 이후 새 밀기까지 네 경우를 검사했다. 관련 패널/상세 테스트
18개가 통과했다. 실제 OS 가장자리 뒤로가기와 화면 읽기 도구는 미검증이다.

빠르게 반대 탭을 누를 때 마지막 선택을 잃을 것이라는 가설도 검사했다. 실제 선택과
실제 PageController 페이지 모두 올바른 0으로 돌아왔다. 최초 진단의 잘못된
기대값 때문에 실패했지만 제품 코드를 고치지 않고 가설을 폐기했다.

## 불필요한 부분과 배터리

- `LocationEnergyPolicy`는 제품 호출 없이 자체 테스트만 있다. 현재 배터리 잔량에
  따라 자동 절전한다고 설명할 근거가 없다.
- `MapPort`/`PlaceholderMapPort`도 제품 참조가 없는 골격이다. 지도는 실제로
  `RouteMap`을 사용한다. TRD와 실제 코드의 계약을 정리할 때 제거 후보로 다룬다.
- 반면 `features/home/session_maintenance_queue.dart`는 application 계층으로 향하는
  기존 import 호환용 re-export다. 이름이 비슷하다는 이유로 중복 구현으로 판정하지 않았다.
- 새 패널에는 비선택 패널의 `TickerMode`와 재생 정지가 이미 있다. 이를 누락된
  배터리 방어라고 보고하지 않는다. 미사용 코드 삭제만으로 GPS 배터리 절감이
  입증되는 것도 아니다.
- 위치 모드별 요청 간격/정확도와 provider 복구는 여전히 실제 기기 비교 측정이
  필요하다. 기존 Samsung 위치 복구를 측정 없이 없애는 변경은 권하지 않는다.

## 보안 경계에서 확인한 방어와 한계

Android 위치 서비스는 `exported=false`, OS 백업 제외 규칙도 유지된다. native
내보내기는 canonical cache 경로를 검사한다. 이번에 URI 기반 임의 파일 유출이나
권한 우회를 새로 입증하지 않았다. 백업의 표/필드 검증과 SQL 바인딩 방어도 존재한다.

추적 파일 목록에서 `.jks`, `.keystore`, `key.properties`, CARTO JSON, `.env` 계열
자격 증명 파일은 발견하지 못했다. 이는 문자열/전체 Git 이력/공개 APK를 대상으로 한
새 비밀정보 검사를 대체하지 않는다. 실제 개인키나 CARTO 설정 파일을 열지 않았다.
지도 예외는 정리된 예외로 바뀌어 키가 붙은 URL을 그대로 전달하지 않는다.

CARTO 클라이언트 키의 APK 추출 가능성, 계정별 사용량/상업용 조건, iOS OS 백업은
기존 운영/공개 전 항목으로 남는다. 이번에는 현재 계정/요금제, 새 CVE 목록, 공개
release APK 역분석을 다시 확인하지 않았다. 정확한 최신 조건을 확인한 것으로
표현하지 않는다. 원본/메모의 공유 안내는 별도 파일 반출 설계로 보완해야 한다.

## 다음 구현 제안

여러 작업을 한 번에 합치지 않는다. 첫 단계는 기존 백업/반출 설계를 승인받아 구현하는
것이다. 50MiB 제한을 읽기 전/도중에 적용하고, 제안한 7일 계산 상한 및 시간/수치
일관성 검사, 집계 실패 시 목록 유지, 정밀 원본 파일 저장과 최소 요약 복사를 함께
다룬다. 외부 파일과 기존 원본은 자동 삭제/절단하지 않는다.

검사 중단의 잘못된 성공 판정은 별도 작은 개발 도구 수정 후보로 둔다. 이후에는
GPS 흔들림과 차량 혼입의 측정 계약, 물리 기기 배터리 기준 측정 순으로 진행한다.
새 서버, 계정, 암호화 SDK를 추가하는 것은 이번 확인 문제를 직접 해결하지 못한다.

보안 설계는 구현자 관점으로 다시 읽어 정상 과거 백업/취소/불완전 집계/모바일
파일 저장 흐름과 대조했다. 사용자 지침의 재위임 금지를 따랐으므로 별도 새 모델의
builder check를 거쳤다고 주장하지 않는다.
